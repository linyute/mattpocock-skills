# 學習記錄格式

學習記錄存放在 `./learning-records/` 中，並使用循序編號：`0001-slug.md`、`0002-slug.md` 等。以惰性方式建立目錄：僅在寫入第一筆記錄時才建立。

它們在教學上相當於架構決策記錄（ADR）：它們記錄非顯而易見的經驗教訓、關鍵洞察，以及將引導未來工作階段的陳述先備知識。它們用於計算近側發展區間（zone of proximal development）。

## 範本

```md
# {所學到或確立內容的簡短標題}

{1-3 句話：學到了什麼（或確立了什麼先備知識），以及為什麼這對未來的工作階段很重要。}
```

這就是完整的格式。學習記錄可以只有一個段落。其價值在於記錄**已知的事實**以及**為什麼**這會改變接下來要教的內容，而不是填滿各個區塊。

## 選用章節

僅在能帶來實質價值時才包含這些章節。大多數記錄都不需要它們。

- **狀態** frontmatter（`active | superseded by LR-NNNN`）：當先前的理解證明有誤並被取代時很有用。
- **佐證**：使用者如何展示其理解（回答了某個問題、完成了一項練習、提及先前的經驗）。當該主張可能會被重新檢視時很有用。
- **影響**：這為未來的工作階段解鎖或排除了什麼。非顯而易見時值得記錄。

## 編號方式

掃描 `./learning-records/` 中的現有最高編號，並遞增一。

## 何時撰寫學習記錄

當符合以下任一條件時，請撰寫一份記錄：

1. **使用者展現了對非淺顯內容的真正理解**：不僅僅是接觸過，而是有證據表明他們能正確運用該概念。這為接下來要教的內容設定了新基準。
2. **使用者透露了先備知識**：「我已經知道 X 了。」記錄下來，以避免未來工作階段重複教學。同時記錄所聲稱的**深度**。
3. **迷思概念得到了修正**：使用者先前相信了錯誤的事情，現在明白了原因。這些具有高價值：它們能預測相關主題未來可能遇到的障礙。
4. **目標因學習而發生轉移**：使用者發現他們關心的事情與原先想像的不同。交互連結至 [[MISSION.md]] 並進行更新。

### 什麼**不符合**資格

- 僅僅只是涵蓋過的教材。涵蓋不等於學習。請等待佐證。
- 任何已簡要記錄在 [[GLOSSARY.md]] 作為詞彙定義的內容。切勿重複。
- 逐個工作階段的活動日誌。學習記錄不是日誌：它們是具備決策價值的洞見。

## 取代

當後續的記錄與先前的記錄相牴觸時（使用者的理解更加深入或獲得糾正），請將舊記錄標記為 `Status: superseded by LR-NNNN`，而不是將其刪除。理解如何演進的歷程本身就是有用的訊號。
