# MISSION.md 格式

`MISSION.md` 位於工作區根目錄。它記錄了使用者學習此主題的**原因**。每一項教學決策（接下來教什麼、呈現哪些資源、設計哪些練習）都應該回溯至此文件。

## 範本

```md
# 目標：{主題}

## 原因
{1-3 句話。使用者正在追求的具體真實世界目標。當他們具備這項技能時，他們的生活或工作會發生什麼改變？避免諸如「了解 X」這類抽象表述；直指根本成果。}

## 成功標準為
- {使用者將能夠執行的具體、可觀察事項}
- {另一項具體事項}
- {…}

## 限制條件
- {時間、預算、先前承諾、學習偏好，任何界定方法範疇的事項}

## 排除範圍
- {使用者明確表示目前不想涉獵的相鄰主題，藉此保護近側發展區間}
```

## 規則

- **每個工作區一個目標。** 若使用者想學習兩件無關的事物，那就是兩個工作區。
- **具體優於抽象。**「在十月前跑完半馬」勝過「變得更健康」。「向團隊交付 Rust CLI」勝過「學習 Rust」。
- **對模糊不清提出質疑。** 若使用者無法清楚說明原因，在撰寫任何內容之前先訪談他們。一個糟糕的目標比沒有目標更糟。
- **隨現實變動進行修訂。** 目標會改變。當使用者的目標轉移時，更新此檔案：切勿讓過時的目標引導未來的工作階段。
- **保持精簡。** 若 `MISSION.md` 超過一個螢幕篇幅，它就不再是指南針，而變成了計畫。
