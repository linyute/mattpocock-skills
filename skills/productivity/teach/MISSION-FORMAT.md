# MISSION.md 格式

`MISSION.md` 存在於工作區根目錄。它擷取使用者正在學習此主題的_原因_。每個教學決策 — 接下來教什麼、浮現哪些資源、設計哪些練習 — 都應追溯至此文件。

## 範本

```md
# Mission: {主題}

## Why
{1-3 句話。使用者正在追求的具體真實世界目標。當他們具備這項技能時，他們的生活或工作會發生什麼改變？避免諸如「為了理解 X」這類抽象構想 — 推動獲得底層成果。}

## Success looks like
- {使用者將能夠做到的具體、可觀察的事物}
- {另一個具體的事物}
- {…}

## Constraints
- {時間、預算、先前的承諾、學習偏好，限制該方法的任何事物}

## Out of scope
- {使用者明確不想在現在追求的鄰近主題 — 保護近側發展區}
```

## 規則

- **每個工作區一個任務。** 如果使用者想學習兩件無關的事物，那就是兩個工作區。
- **具體優於抽象。** 「在十月前跑半程馬拉松」勝過「變得更健康」。「向我的團隊交付 Rust CLI」勝過「學習 Rust」。
- **反駁模糊不清。** 如果使用者無法說明原因，在撰寫任何內容之前先訪談他們。糟糕的任務比沒有任務更糟。
- **當現實改變時進行修訂。** 任務會改變。當使用者的目標移動時，更新此檔案 — 不要留下過時的任務來引導未來的會話。
- **保持簡短。** 如果 `MISSION.md` 超過一個螢幕，它就已經不再是指南針，而是開始成為計劃了。
