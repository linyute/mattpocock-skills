# 技能機制

[`writing-for-agents`](SKILL.md) 針對技能的分支：當文件是技能時的相異之處（frontmatter、呼叫方式選擇與路由器技能）。關於撰寫它的所有其他內容皆屬於 `SKILL.md` 中的通用參考。

## 呼叫方式

兩種選擇，權衡兩種負載：

- **模型呼叫**的技能會保留 `description`，使代理人能自主觸發它，且其他技能也能存取它。您仍然可以鍵入其名稱：模型呼叫始終**包含**使用者呼叫；description 只會增加代理人的探索發現能力，絕不會移除人類的存取能力。此 description 是該技能的頂層上下文指標，被強制隨時保持載入：以永久的上下文負載換取可探索性。內容完全為參考資料的模型呼叫技能也是共用參考資料的一種歸宿：另一個技能可以呼叫它，因此數個技能所需的參考資料便能集中在同一個地方。機制：省略 `disable-model-invocation`，並撰寫帶有觸發分支的面對模型 description（`SKILL.md` 中的指標撰寫規則完全適用）。
- **使用者呼叫**的技能將 description 從代理人的接觸範圍中移除：只有鍵入其名稱的人類才能呼叫它，任何其他技能都無法呼叫。零上下文負載，但它會消耗認知負載：您就是必須記住其存在的索引。機制：設定 `disable-model-invocation: true`；`description` 轉為面向人類：單行摘要，移除觸發詞清單。

僅在代理人必須自行存取該技能，或另一項技能必須存取它時，才選擇模型呼叫。若它僅會手動觸發，請將其設為使用者呼叫，不需承擔任何上下文負載。

兩個使用者呼叫的技能共同需要的共用參考資料不能存在於兩者任一之中：由於沒有 description，兩者都無法觸發對方。將其移至技能系統之外的純文字檔案：任何技能都可以指向的外部參考資料。

## 依呼叫方式拆分

依呼叫拆分的方式（循序拆分見於 `SKILL.md`）：當您有一個應當單獨觸發該技能的獨特開頭詞彙（您在提示詞中實際使用的觸發詞彙），或者另一個技能必須存取它時，拆分出一個模型呼叫技能。您需要為新的常駐載入 description 支付上下文負載，因此該獨立存取必須具備相應價值。

## 路由器技能

當使用者呼叫的技能倍增到超出您所能記住的範圍時，這種累積的認知負載可由**路由器技能**來解決：一個使用者呼叫的技能，指明其他技能以及何時該使用每一項技能，讓人類只需記住一個技能而非多個技能。它只能提供提示，絕不能觸發它們：使用者呼叫的技能沒有 description，因此除了人類之外沒有任何事物能存取它們。
