# 技能機制（Skill mechanics）

[`writing-for-agents`](SKILL.md) 的技能特定分支：當文件是技能時發生改變的內容 — Front matter、呼叫選擇與路由技能。關於撰寫它的所有其他內容皆為 `SKILL.md` 中的通用參考。

## 呼叫（Invocation）

兩種選擇，權衡兩種負載：

- **模型呼叫（model-invoked）**技能保留 `description`，使 Agent 能自主觸發它 — 且其他技能也能存取它。您仍然可以輸入其名稱：模型呼叫始終_包含_使用者可及性；描述只會新增 Agent 的可發現性，絕不會移除人類的可及性。描述是技能頂層的上下文指標，被強制隨時保持載入 — 以永久的上下文負載換取可發現性。內容全為參考的模型呼叫技能也是共享參考的一個家：另一個技能可以呼叫它，因此多個技能所需的參考可以存在於同一個地方。機制：省略 `disable-model-invocation`，並撰寫承載觸發分支的面向模型的描述（`SKILL.md` 中的指標撰寫規則完全適用）。
- **使用者呼叫（user-invoked）**技能從 Agent 的可及範圍中剝離描述：只有輸入其名稱的人類才能呼叫它，沒有其他技能可以呼叫它。零上下文負載，但它會消耗認知負載 — 您是必須記住其存在的索引。機制：設定 `disable-model-invocation: true`；`description` 變成面向人類的 — 單行摘要，剝離觸發清單。

僅在 Agent 必須自行存取技能或另一個技能必須存取時，才選擇模型呼叫。如果它只會手動觸發，將其設為使用者呼叫且不支付任何上下文負載。

兩個使用者呼叫技能都需要的共享參考不能存在於任何一個之中 — 在沒有描述的情況下，兩者都無法觸發對方。將其推送到技能系統之外的純檔案中：任何技能都可以指向的外部參考。

## 按呼叫拆分

拆分的呼叫切割（順序切割存在於 `SKILL.md` 中）：當您擁有應該單獨觸發模型呼叫技能的獨特引導詞（您在提示詞中實際使用的觸發詞）或另一個技能必須存取它時，拆分出模型呼叫技能。您為新始終載入的描述支付上下文負載，因此獨立的可及性必須是值得的。

## 路由技能

當使用者呼叫技能繁殖超過您可以記住的程度時，堆積的認知負載可以透過**路由技能（router skill）**來解決：一個命名其他技能以及何時調用每個技能的使用者呼叫技能，使人類只需記住一個技能而非許多技能。它只能給出提示，絕不能觸發它們：使用者呼叫技能沒有描述，因此除了人類之外沒有任何東西可以存取它們。
