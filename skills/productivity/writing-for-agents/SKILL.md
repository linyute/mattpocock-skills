撰寫 Agent 所消費的任何文件（技能、`AGENTS.md` / `CLAUDE.md`、透過指標到達的文件）的參考資料。封裝有所不同；寫作則不然：相同的槓桿使每一個都可預測 — 使 Agent 在每次執行中採取相同的_流程_，而不是產生相同的輸出。

當您撰寫的文件是技能時，請閱讀 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 以瞭解 Front matter、呼叫選擇與路由技能。

## 上下文指標

**上下文指標（context pointer）**是 Agent 上下文中保留的參考，命名了某些上下文之外的材料並編碼了到達該材料的條件。技能的描述就是一個；`AGENTS.md` 中命名文件的行也是相同的物件。指標的_措辭_而非其目標，決定了 Agent 何時到達該材料 — 以及多麼可靠。弱措辭指標背後的必備目標是變異 Bug：首先磨礪措辭，僅當磨礪失敗時才將材料內聯。

指標承擔兩項工作 — 陳述材料是什麼，並列出應該觸發到達該材料的**分支（branches）**（分支是文件處理的不同個案，因此不同的執行會採取穿過它的不同路徑）。始終載入的指標的每個字在每一輪都會產生成本，因此它比主體賺取了更嚴格的修剪：

- **前置引導詞（leading word）** — 指標是其進行觸發工作的地方。
- **每個分支一個觸發器。** 重命名單一分支的同義詞是寫了兩次的同一個分支；折疊它們並僅保留真正不同的分支。
- **剪掉主體已經承載的身份資訊。**

## 兩種負載

您新增的每個文件與指標都會消耗兩種預算之一：

- **上下文負載（Context load）** — 始終載入的材料在 Agent 視窗上的成本：`AGENTS.md` 行、技能描述、每一輪都停留在上下文中的任何內容，無論是否觸發都會消耗 Token 與注意力。
- **認知負載（Cognitive load）** — 對人類的成本：存在哪些文件以及何時調用每一個。人類就是索引。不是要最小化的成本 — 它是人類主體性的代價；在人類判斷重要的地方消耗它，在不重要的地方移除它。

僅透過指標到達的材料以指標本身行的代價逃避了上下文負載；完全沒有指標的材料則完全依賴認知負載。

## 資訊層級

文件由兩種內容型態建構而成 — **步驟（steps）**（Agent 執行的有序動作）與**參考（reference）**（按需查閱的定義、規則、事實）— 它們自由混合：全步驟（食譜）、全參考（審查的規則、本技能）或兩者兼有。核心決策是每塊內容在**資訊層級（information hierarchy）**上的位置，這是一個按 Agent 需要材料的即時程度排列的梯子：

1. **檔案內步驟** — 主要層級：Agent 按順序做的事。
2. **檔案內參考** — 按需查閱。通常是合法的扁平對等集合（審查的條規則都在一個梯級上）— 良好的安排，非壞味道。
3. **揭露的參考** — 推送至單獨的檔案中，透過上下文指標到達，僅在指標觸發時載入。跨越相同資料夾中的兄弟檔案，直到存在於任何地方且任何文件都可以指向的完全外部參考。

向下推太少頂部會膨脹；向下推太多則會隱藏 Agent 實際上需要的材料。這種張力就是整個決策。

**漸進式揭露（Progressive disclosure）**是沿著梯子向下的移動 — 移出主檔案並放在指標背後 — 使頂部保持可讀性。主要不是 Token 最佳化：而是層級如何受到保護的方式。分支是最乾淨的揭露測試：內聯每個分支需要的內容，並將僅有部分分支到達的內容推送到指標背後。當文件帶有步驟時，應該被揭露的檔案內參考會掩埋它們，並將注意力轉變成拋硬幣 — 這是一個變異槓桿，而不僅僅是可讀性槓桿。

**同處放置（Co-location）**是檔案內部的伴侶：梯子決定一件內容放置在_多深的梯級上_，同處放置則決定到達該處後_什麼放置在其身旁_。將概念的定義、規則與注意事項保留在一個標題下，而不是分散在各處，因此閱讀一個部分會帶來其鄰居。測試：文件讀起來應該像為 Agent 撰寫的文件 — 分組材料讀起來是那樣；分散材料則不然。（與重複不同：重複會在兩個地方重述同一個含義；分散則將一個含義碎片化跨越許多地方。）

**蔓延（Sprawl）**是此處的失敗模式：文件單純太長，即使每一行都是實時且唯一的。注意力在過多內容中稀釋，且每一行額外的內容都是維護相關性的額外負擔。解藥是梯子：在指標背後揭露參考，並按分支或順序進行拆分，使每條路徑僅承載其需要的內容。

## 步驟與完成標準

每個步驟都以**完成標準（completion criterion）**結束 — 告知 Agent 工作完成的條件。兩項屬性使其成為槓桿：

- **清晰度（Clarity）** — Agent 能區分已完成與未完成嗎？模糊的界限（「達到理解」）會招致**過早完成（premature completion）**：在步驟真正完成前結束它，注意力滑向_完成狀態_。前方仍可見的步驟 — **完成後步驟（post-completion steps）** — 提供拉力；標準的清晰度則是阻力。按順序防禦：**首先磨礪界限**（局部且廉價）；僅當界限不可簡化地模糊_且_您觀察到急躁時，透過拆分順序來隱藏較晚的步驟 — 且隱藏僅能跨越真實的上下文邊界運作（交接或子 Agent 調度；內聯呼叫會將較晚的步驟留在上下文中且不會清空任何內容）。
- **需求度（Demand）** — 它要求的程度。「核對每個修改過的模型」會強制進行徹底的工作，而「產生變更清單」則不會。需求度會驅動**腿力工作（legwork）** — Agent 在工作內部進行的挖掘，潛藏於措辭中而非寫為獨立步驟 — 且它不受步驟限制：「套用每條規則」綁定全參考主體，正如「完成每個步驟」綁定順序一樣，這正是全參考文件如何仍承載詳盡性標準的原因。

最強大的標準既可檢查又詳盡。

## 何時拆分

將一個文件拆分為兩個會消耗兩種負載之一，因此僅在裁切值得時才進行拆分：

- **按順序** — 在完成後步驟誘惑 Agent 急於完成眼前步驟的地方拆分一連串步驟。將它們保留在視線之外可以在當前任務上驅動更多的腿力工作。謹防反向操作：合併順序會將每個步驟的較晚步驟暴露給後續內容，從而招致過早完成。
- **按呼叫** — 技能特定：參見 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引導詞（Leading words）

**引導詞（leading word）**是已經存在於模型預訓練中的緊湊概念，Agent 在執行文件時會用其思考（_lesson_、_fog of war_、_tracer bullets_）。作為 Token 重複出現（絕非作為句子），它透過招募模型已經持有的先驗，累積分散式定義並在最少的 Token 中錨定整塊行為區域。如果您清晰定義自己的詞是可以運作的，但造出的詞不會招募任何先驗 — 您花費定義 Token 支付預訓練詞免費提供的內容；優先調用現有的詞。

它會錨定兩次。在主體中，_執行_：每次該詞出現時 Agent 都會採取相同的行為，且在扁平參考內部它將注意力集中在一類尋找的事物上。在指標中，_呼叫_：當相同的詞存在於您的提示詞、您的文件與您的程式碼庫中時，Agent 會將該共享語言連結至材料並更可靠地存取它。

尋找使用引導詞進行重構的機會。在三個站點拼寫出來的三元組，花費一個句子打手勢指向一個想法的指標 — 每一個都是渴望折疊成單一 Token 的段落：

- 「快速、確定性、低開銷」 → _tight_（_tight_ 迴圈）。
- 「您相信的迴圈」 → _red_ — 模糊的關卡變成二元可觀察狀態（迴圈在 Bug 上變 _red_，或者沒有）。

您會贏兩次：更少的 Token，以及供 Agent 懸掛其思考的更犀利鉤子。

**否定（Negation）**是此槓桿旁邊的失敗模式：透過禁止來引導會將被禁止的行為拖入上下文中，並使其變得_更_可用，而不是更少。_不要想像一隻大象_，大象就是所有的內容；否定是一個弱修飾語，被強活化的概念所超越，因此禁令半讀半解就像做該事的指示。提示**正面（positive）**內容 — 陳述目標行為（「撰寫單行註解」），使被禁止的行為永遠不被說出。禁止僅有在作為您無法正面措辞的硬性安全護欄時才能贏得其位置；即使在那時，將其與正面目標搭配，使注意力落在該做什麼上。

## 修剪（Pruning）

- 將每個含義保留在**單一事實來源（single source of truth）**中：一個權威的位置，因此變更行為是一處編輯。**重複（Duplication）** — 相同含義出現在一個以上的位置 — 會消耗維護與 Token，並將含義在梯子上的突出度膨脹超過其真實等級。（引導詞的意外反向，引導詞是故意重複 Token，絕非重複含義。）
- **環境**也是事實來源 — `package.json` 腳本、設定檔案、目錄佈局、`--help` 輸出 — 且重述它的文件是**快取（cache）**：查找的副本，僅在查找非常昂貴時才賺取其負載。快取 Agent 無法透過尋找獲得的內容：未寫出的慣例、選擇背後的原因、沒有設定坦白的陷阱。將單檔案、單命令的查找留給環境，在該處它們不會過時。
- 檢查每一行的**相關性（relevance）**：它是否仍與文件的作用相關？一行內容因從未與任務相關（單純的闡述，或是應該被揭露的分支）或隨著它所描述的行為或世界發生變化而過時而失去相關性。較短的文件更容易保持相關性。如果沒有修剪紀律，預設的命運是**沉積物（sediment）**：因為新增感覺安全而移除感覺有風險而沉澱的過時層，直到您必須向下鑽穿它們以尋找仍然活著的內容。
- 逐句尋找**無作業（no-ops）**：模型預設已遵守的指示支付負載卻什麼都沒說。測試 — 相對於預設它是否改變了行為？ — 是相對於模型的，而不是相對於讀者的：兩個人就無作業產生分歧，是對預設產生分歧，並透過執行文件來解決，而不是透過辯論。當一個句子失敗時，刪除整個句子而不是從中修剪單字。測試也為引導詞分級：太弱而無法擊敗預設的詞（當 Agent 已經大致徹底時使用 _be thorough_）是無作業，修復方法是更強的詞（_relentless_），而非不同的技巧。
