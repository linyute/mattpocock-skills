# 範疇之外知識庫

儲存庫中的 `.out-of-scope/` 目錄儲存被拒絕功能請求的持久記錄。它有兩個目的：

1. **機構記憶** — 功能被拒絕的原因，因此當議題關閉時推理不會遺失
2. **去重** — 當傳入與先前的拒絕匹配的新議題時，該技能可以浮現先前的決策，而不是重新爭論

## 目錄結構

```
.out-of-scope/
├── dark-mode.md
├── plugin-system.md
└── graphql-api.md
```

每個**概念**一個檔案，而不是每個議題一個。請求相同事物的大量議題會分組在單一檔案底下。

## 檔案格式

檔案應以輕鬆、可讀的風格撰寫 — 更像短小的設計文件而非資料庫條目。使用段落、程式碼範例與範例使推理清晰，並對第一次遇到的人有用。

```markdown
# Dark Mode

此專案不支援深色模式或面向使用者的主題設定。

## Why this is out of scope

渲染管線假設使用在 `ThemeConfig` 中定義的單一色彩調色盤。
支援多個主題需要：

- 包裹整個元件樹的主題上下文提供者
- 每個元件的主題感知樣式解析
- 用於使用者主題偏好設定的持久化層

這是一項重大的架構變更，與專案對內容創作的專注
不符。主題設定是嵌入或重新分發輸出的下游
消費者的關切事項。

```ts
// 現有的 ThemeConfig 介面並非專為執行階段切換而設計：
interface ThemeConfig {
  colors: ColorPalette; // 單一調色盤，在建構階段解析
  fonts: FontStack;
}
```

## Prior requests

- #42 — "Add dark mode support"
- #87 — "Night theme for accessibility"
- #134 — "Dark theme option"
```

### 命名檔案

為概念使用簡短、具描述性的 kebab-case 名稱：`dark-mode.md`、`plugin-system.md`、`graphql-api.md`。名稱應足夠容易識別，使瀏覽目錄的人無需開啟檔案就能理解被拒絕了什麼。

### 撰寫原因

原因應具備實質內容 — 不是「我們不想要這個」而是原因。良好的原因參考：

- 專案範疇或哲學（「此專案專注於 X；主題設定是下游的關切事項」）
- 技術約束（「支援此功能需要 Y，這與我們的 Z 架構衝突」）
- 戰略決策（「我們選擇使用 A 而非 B，因為…」）

原因應該是耐用的。避免引用臨時情況（「我們現在太忙了」）— 那不是真正的拒絕，而是延後處理。

## 何時檢查 `.out-of-scope/`

在分揀期間（步驟 1：收集上下文），閱讀 `.out-of-scope/` 中的所有檔案。在評估新議題時：

- 檢查請求是否符合現有的範疇之外概念
- 匹配是依據概念相似度而非關鍵字 — "night theme" 符合 `dark-mode.md`
- 如果有匹配項，向維護者浮現出來：「這與 `.out-of-scope/dark-mode.md` 類似 — 我們之前因為 [原因] 拒絕了此功能。您現在仍然有同感嗎？」

維護者可能會：

- **確認** — 新議題被新增至現有檔案的 "Prior requests" 清單中，然後關閉
- **重新考慮** — 範疇之外檔案被刪除或更新，且議題通過正常分揀
- **不贊同** — 這些議題相關但不同，進行正常分揀

## 何時寫入 `.out-of-scope/`

僅當**增強功能**（非 Bug）被*拒絕*為 `wontfix` 時。這完全適用於增強功能 PR，就像適用於議題一樣 — 被拒絕的 PR 會記錄在此處，使相同的請求不會作為新鮮程式碼捲土重來。

當某內容因為**已經實作**而被關閉為 `wontfix` 時，**切勿**寫入此處。那是已建構的功能，而非被拒絕的功能；記錄它會以虛假的拒絕毒害去重檢查。相反，關閉留言應指向該功能已經存在的位置。

流程：

1. 維護者決定某功能請求超出範疇
2. 檢查是否存在匹配的 `.out-of-scope/` 檔案
3. 如果是：將新議題附加至 "Prior requests" 清單
4. 如果否：建立一個包含概念名稱、決策、推理與第一個先前請求的新檔案
5. 在議題上發布留言說明決策，並提及 `.out-of-scope/` 檔案
6. 使用 `wontfix` 標籤關閉議題

## 更新或移除範疇之外檔案

如果維護者改變了對先前被拒絕概念的想法：

- 刪除 `.out-of-scope/` 檔案
- 該技能不需要重新開啟舊議題 — 它們是歷史記錄
- 觸發重新考慮的新議題將通過正常分揀
