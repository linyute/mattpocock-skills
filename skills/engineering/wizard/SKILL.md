# 精靈 (Wizard)

**精靈（Wizard）** 是一個 Bash 指令碼，它逐步引導人類完成手動程序，這些程序手動執行既繁瑣，每次向 AI 重新解釋也同樣繁瑣。它會開啟每個 URL，確切說明要按一下並複製什麼，擷取這些數值，將它們寫入適當位置（`.env`、GitHub 密鑰），在每個階段進行確認，並顯示還剩下多少階段。它可能會設定第三方服務、執行一次性遷移，或將專案從一種狀態轉移到另一種狀態。

愉悅的 UX 已經由 [template.sh](template.sh) 解決：逐階段進度、確認閘道、跨平台 URL 開啟（包含 WSL）、隱藏密鑰輸入、具等冪性的 `.env` 更新、`gh secret`/`gh variable` 寫入以及結尾摘要。**你的工作僅在於設定程序的範圍並編寫其階段。** `STAGES` 標記上方的函式庫在每個精靈中都相同；這種一致性是重點所在：絕不要手動編輯它。

精靈預設為暫時性的：針對單次執行建構，儲存到臨時或 `scripts/` 路徑，工作完成後即刪除。僅在使用者想要一個應保留在儲存庫中的可重複設定路徑時，才將其認可提交。

## 流程

### 1. 界定程序範圍

釐清人類必須採取的所有手動步驟，以及在此過程中擷取的所有數值。請先閱讀儲存庫，不要毫無準備地提問：

- 針對設定：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、架構設定以及 `.github/workflows/*`（每個 `secrets.*` / `vars.*` 參照都是精靈必須產生的數值）。
- 針對遷移或轉移：目前狀態、目標狀態，以及它們之間不可逆的動作。

然後向使用者顯示依序排列的階段清單及其各自產生的數值，並進行確認：他們可以新增、刪除或重新排序。

**完成標準：** 每個階段都依序命名，且對於每個擷取的數值，你都知道 (a) 人類從何處取得它、(b) 它寫入何處（`.env`、GitHub 密鑰、兩者皆是，或無處寫入；有些階段純粹是動作），以及 (c) 它是秘密（隱藏輸入）還是公開的。

### 2. 規劃每個階段的旅程

針對每個階段，寫出人類依循的精確路徑：要開啟哪個 URL、在那裡做什麼、數值顯示在何處、它填入哪個變數：例如「資訊主頁 → 開發者 → API 金鑰 → 顯示測試金鑰 → 複製」。凡是你實際上不知道目前 UI 或確切指令的地方，請如實說明並詢問使用者或查閱文件：絕不要捏造可能不存在的步驟。

**完成標準：** 每個階段都能追溯到陌生人都能遵循的具體指示。

### 3. 編寫精靈

將 `template.sh` 複製到目標路徑。將範例階段替換為每個步驟一個 `stage`，依相依性排序。使用函式庫輔助函式：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。將 `TOTAL_STAGES` 設為你編寫的階段數量。

保持範本設定的標準：在要求輸入數值之前開啟 URL、對任何敏感內容使用 `ask_secret`、`write_env` 每個持久化數值、`set_secret` 僅限 CI 實際需要的數值，並在任何不可逆動作之前執行 `confirm`。每個 `stage` 都會清除畫面，以便僅顯示目前的步驟：將階段保持在一個專注的任務上，這樣人類所需的一切就不會被滾動移出畫面。請勿更動標記上方的函式庫。

### 4. 驗證與交付

- `bash -n <script>`；若可用請執行 `shellcheck`。
- `chmod +x <script>`。
- 不要自己端對端執行它：它會開啟瀏覽器並阻斷等待人類輸入。改為以靜態方式追蹤它：步驟 1 中的每個數值都已擷取並存入步驟 1 所述的位置，且每個 `set_secret` 名稱都與 CI 中的 `secrets.*` 參照完全相符。
- 告訴使用者如何執行它。如果這是可重複的設定路徑，請將其認可提交並從 README 進行連結，以便下一個人執行指令碼，而非詢問 AI。
