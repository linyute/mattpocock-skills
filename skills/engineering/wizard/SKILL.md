# 嚮導（Wizard）

**嚮導（wizard）**是一個 Bash 腳本，一步一步引導人類完成手動操作繁瑣且每次向 AI 重新解釋都很繁瑣的手動程序。它會開啟每個 URL，精準說明要點擊與複製的內容，擷取數值，將它們寫入所屬位置（`.env`、GitHub secrets），在每個階段進行確認，並顯示還剩下多少個階段。它可能會設定第三方服務、執行一次性遷移，或將專案從一個狀態移動至另一個狀態。

令人愉悅的 UX 已經由 [template.sh](template.sh) 解決 — 分階段進度、確認關卡、跨平台 URL 開啟（包含 WSL）、隱藏密鑰輸入、冪等 `.env` 插入或更新、`gh secret`/`gh variable` 寫入，以及結尾摘要。**您的工作僅為劃定程序範疇並撰寫其階段。** `STAGES` 標記之上的函式庫在每個嚮導中都是相同的；這種一致性即為重點 — 絕不手動編輯它。

嚮導預設為暫時性的 — 為單次執行而建構，儲存至草稿或 `scripts/` 路徑，當工作完成時刪除。僅當使用者想要一個應存在於儲存庫中的可重複設定路徑時才提交它。

## 流程

### 1. 劃定程序範疇

找出人類必須採取的每個手動步驟以及沿途擷取的每個數值。最先閱讀儲存庫 — 不要冷不防地詢問：

- 關於設定：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架設定，以及 `.github/workflows/*`（每個 `secrets.*` / `vars.*` 引用都是嚮導必須產生的數值）。
- 關於遷移或轉移：當前狀態、目標狀態，以及它們之間的不可逆動作。

然後向使用者展示有序的階段清單與各階段產生的數值並進行確認 — 他們可能會新增、捨棄或重新排序。

**完成條件：** 每個階段都按順序命名，且對於每個擷取的數值您都知道 (a) 人類從何處取得它、(b) 它被寫入何處（`.env`、GitHub secret、兩者皆有或無處 — 有些階段是純動作），以及 (c) 它是否為密鑰（隱藏輸入）或公開內容。

### 2. 規劃每個階段的歷程

對於每個階段，寫下人類遵循的精準路徑：開啟哪個 URL、在該處做什麼、在何處顯示數值、填入哪個變數 — 例如「Dashboard → Developers → API keys → Reveal test key → copy」。在您實際上不知道當前 UI 或精準命令之處，請說明並詢問使用者或檢查文件 — 切勿發明可能不存在的步驟。

**完成條件：** 每個階段都能追溯至陌生人也能遵循的具體指示。

### 3. 撰寫嚮導

將 `template.sh` 複製至目標路徑。按依賴順序，以每個步驟一個 `stage` 替代範例階段。使用函式庫輔助常式 — `stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm` — 並將 `TOTAL_STAGES` 設定為您撰寫的階段數量。

堅守範本設定的標準：在詢問其數值前先開啟 URL、對任何密鑰使用 `ask_secret`、對每個持久化的數值使用 `write_env`、僅對 CI 實際需要的數值使用 `set_secret`，並在任何不可逆動作前進行 `confirm`。每個 `stage` 都會清空螢幕使僅當前步驟可見 — 將一個階段保持為單一專注任務，使人類需要的任何內容都不會滾走。不要接觸標記之上的函式庫。

### 4. 驗證與移交

- `bash -n <script>`；若可用請執行 `shellcheck`。
- `chmod +x <script>`。
- 不要自己端對端執行它 — 它會開啟瀏覽器並阻塞在人類輸入上。改為進行靜態追蹤：步驟 1 的每個數值都被擷取並降落於步驟 1 所說明的位置，且每個 `set_secret` 名稱完全符合 CI 中的 `secrets.*` 引用。
- 告知使用者如何執行它。如果這是可重複的設定路徑，提交它並從 README 進行連結，使下一個人執行腳本而非詢問 AI。
