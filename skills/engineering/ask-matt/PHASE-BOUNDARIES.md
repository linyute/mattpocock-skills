# 階段邊界 (Phase boundaries)

**階段 (phase)** 是工作階段內的一大塊工作：盤問、實作、QA。此定義特意保持模糊：當您認為*「好，那部分完成了」*時，階段即告結束。

**階段邊界 (phase boundary)** 是兩個階段之間的間隔，且是此決策所屬的唯一之處。在階段進行中無需做此決策：繼續進行，或將剩餘工作拆分給子代理。在階段中進行壓縮會使代理遺失脈絡。

## 五種選項

| 選項 | 功能說明 |
| ------------ | --------------------------------------------------------------- |
| **Continue** | 留在工作階段中。完全不進行上下文切換。 |
| **`/clear`** | 清空上下文視窗並從頭開始。 |
| **`/handoff`** | 撰寫可攜式 Markdown 檔案並以此在任何地方啟動新工作階段。 |
| **Subagent** | 將任務傳送至其專屬的上下文視窗並取得報告回傳。 |
| **`/compact`** | 壓縮此上下文並以摘要啟動全新的工作階段。 |

## 決策樹

在邊界處由上而下進行評估。第一個 **yes** 即為解答。

**1. 您能在這個工作階段中繼續嗎？** 兩件事會使答案為 yes：下一個階段需要本階段作為**原始來源**，或者您剩下的[聰明區 (smart zone)](https://www.aihero.dev/ai-coding-dictionary/smart-zone) 足夠（約 15 萬 tokens）容納下一個階段。盤問 → 實作是標準的 yes：實作需要逐字完整的推論，而非其摘要。繼續不需要成本也不會遺失任何東西，因此在考慮其他選項前先排除它。

**2. 上下文是否與接下來的內容無關？** 此工作階段中的所有內容（探索、決策、死胡同）是否皆可拋棄？如果是，**`/clear`**。這是盤面上最廉價的舉措：不花費時間並歸還整個視窗。`/clear` 也不是終局性的：舊工作階段仍可恢復。

弄錯此步驟的代價是單向的。清除*相關*的上下文，您就會失去所建構內容背後的**原因**，事後再怎麼重讀 diff 也無法挽回。

**3. 您需要交接嗎？** `/handoff` 的適用範圍很窄。您僅在下列情況才需要它：

- 切換至**新框架 (harness)**（Claude → Codex），
- 移動至**新目錄**或儲存庫，
- 將工作傳送給**同事**，
- 或在**階段中**分叉出您發現的旁支任務，而不會偏離您正在做的事。

該清單即為全部條件。`/handoff` 換取的是**可攜性**：一個可以隨處移動的檔案。如果沒有任何東西需要移動，您就不需要它。

**4. 任務可以非同步 (AFK) 完成嗎？** 它的範疇是否足夠明確，讓您離開鍵盤無需引導即可執行？如果是，請將其傳送至**子代理**，並保持此工作階段不變。自動化審查是標準案例：代理讀取 diff 並回報，且在執行時不需要您。

**5. 否則，使用 `/compact`。** 相關上下文、相同框架、相同目錄，且您需要保持參與：這就是決策樹的歸宿，且經常落在此處。傳遞一項指示（`/compact 我們將對此區域進行 QA`），以便摘要保留下一個階段所需的內容。

`/compact` 是**預設值，而非第一首選**。它位於底部，因為其上方的四個問題都更廉價或更精確。當人們由此開始時的失敗模式是：新工作階段對摘要中被扁平化的決策表現出自信的錯誤。

## 原始來源與次要來源

除了 **Continue** 之外的每種舉措，都會將**原始來源**轉變為**次要來源**：工作階段的真實發生過程，被其摘要所取代。權衡取捨始終具有相同的形式：

| 來源 | 資訊 | 雜訊 | 挪移空間 |
| --------------------------------- | ----------- | ----- | ------------ |
| 原始來源 (Continue) | 完整 | 很多 | 很少 |
| 次要來源 (`/compact`, `/handoff`) | 有損 | 較少 | 很多 |

這就是為什麼問題 1 排在第一位。只有當留下來的成本高於所節省的成本時，您才承擔有損的代價。

## 這些是主觀判斷

這些問題並非客觀的：每個問題都帶有品味，且相同的邊界在不同日子可能產生兩種結果。其價值在於**按順序**提問，且在邊界處而非工作途中進行提問。
