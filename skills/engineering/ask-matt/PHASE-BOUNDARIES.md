# 階段邊界

一個**階段（phase）**是會話內部的一塊工作 — 審問、實作、QA。此定義故意保持模糊：當您認為*「好的，我們完成那個了」*時，階段即告結束。

**階段邊界**是兩個階段之間的空隙，而且這是唯一適合做出此決策的地方。在階段中途沒有需要做出的決策 — 繼續進行，或將剩餘的工作拆分給子 Agent。在階段中途進行壓縮會讓 Agent 失去思路。

## 五個選項

| 選項 | 功能 |
| ------------ | --------------------------------------------------------------- |
| **Continue** | 留在會話中。完全不進行上下文切換。 |
| **`/clear`** | 清空上下文視窗並從頭開始。 |
| **`/handoff`** | 撰寫一個可攜式的 Markdown 檔案，並在任何地方用它播種會話。 |
| **Subagent** | 將任務傳送到其專屬的上下文視窗並接收回覆報告。 |
| **`/compact`** | 壓縮此上下文，並用摘要播種一個全新的會話。 |

## 決策樹

在邊界處由上至下評估。第一個 **是** 勝出。

**1. 您可以在此會話中繼續嗎？** 兩件事會使答案為「是」：下一個階段需要將此階段作為**主要來源**，或者您剩下的 [smart zone](https://www.aihero.dev/ai-coding-dictionary/smart-zone) 容量足夠（~150k tokens）容納下一個階段。審問 → 實作是標準的「是」：實作需要原汁原味的推理過程，而不是其摘要。繼續（Continue）零成本且無損失，因此在做其他事之前先進行評估。

**2. 上下文是否與接下來的內容無關？** 此會話中的一切內容 — 探索、決策、死胡同 — 是否都可以拋棄？如果是，請使用 **`/clear`**。這是最省資源的操作：不花費時間，並還給您整個視窗。`/clear` 也不是終結性的 — 舊會話仍可恢復。

弄錯這一點的代價是單向的。清空*相關*的上下文，您將失去建構內容背後的**原因**，事後再怎麼閱讀差異（diff）也無法挽回。

**3. 您需要交接嗎？** `/handoff` 的適用情境很窄。只有當您具備以下情況時才需要：

- 切換至**新的 Harness**（Claude → Codex），
- 移動至**新的目錄**或儲存庫，
- 將工作發送給**同事**，
- 或分支在**階段中途**發現的旁支任務，而不會偏離正在進行的工作。

上述清單就是全部條件。`/handoff` 帶來的是**可攜性** — 一個可移動的檔案。如果沒有任何東西需要移動，您就不需要它。

**4. 任務可以離線（AFK）完成嗎？** 它的範疇是否足夠緊湊，讓您離開鍵盤時也能執行，無需引導？如果是，請將其傳送給**子 Agent**，並保持此會話原封不動。自動審查是標準案例：Agent 閱讀差異並回報，執行時您不需要在場。

**5. 否則，使用 `/compact`。** 相關上下文、相同的 Harness、相同的目錄，且您需要保持參與 — 這就是決策樹最終停留之處，且經常停在這裡。傳入指示（`/compact we're going to QA this area`），以便摘要保留下一個階段所需的內容。

`/compact` 是**預設值，但不是首選**。它位於底部是因為上面的四個問題都更省資源或更精準。人們從這裡開始的失敗模式是：在一個全新的會話中，對於已被摘要平坦化的決策產生自信但錯誤的理解。

## 主要與次要來源

除了 **Continue** 之外的每個操作，都會將**主要來源**轉變為**次要來源** — 發生的會話過程被其摘要所取代。權衡形式始終相同：

| 來源 | 資訊 | 雜訊 | 移動空間 |
| --------------------------------- | ----------- | ----- | ------------ |
| 主要（Continue） | 完整 | 多 | 少 |
| 次要（`/compact`、`/handoff`） | 有損 | 較少 | 多 |

這就是為什麼問題 1 放在首位。只有當留下來的成本高於所節省的成本時，您才需要承擔有損的代價。

## 這些是裁量判斷

這些問題並非客觀的 — 每個問題都有其衡量標準，相同的邊界在不同的兩天可能會有不同的結果。價值在於**按順序**在邊界處詢問這些問題，而不是在工作進行的中途。
