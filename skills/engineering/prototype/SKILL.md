# 原型

原型是**用於回答問題的拋棄式程式碼**。由問題來決定其形式。

## 選擇分支

透過使用者的提示、周圍的程式碼，或者若使用者在場時透過詢問，確認正在回答哪個問題：

- **「這個邏輯／狀態模型感覺對嗎？」** → [LOGIC.md](LOGIC.md)。建構單一可分享的 HTML 檔案（自由操作按鈕外加分頁式引導逐步操作），將狀態機推向在紙面上難以推論的案例，且非開發人員也能操作。
- **「這應該長成什麼外觀？」** → [UI.md](UI.md)。在單一路由上產生數種截然不同的 UI 變體，可透過 URL search param 與浮動底列進行切換。

這兩個分支產生的工件截然不同，因此選錯會浪費整個原型。若問題確實含糊不清且無法聯絡到使用者，請預設使用與周圍程式碼較為吻合的分支（後端模組 → 邏輯；頁面或元件 → UI），並在原型頂端陳述該假設。

## 兩者皆適用的規則

1. **從第一天起就是用過即丟的，並清楚標示。** 將原型程式碼放置在實際使用的位置附近（鄰近其正在原型的模組或頁面），使上下文一目了然，但命名時要讓隨意瀏覽的讀者能看出這是原型而非正式環境。針對用過即丟的 UI 路由，請遵循專案現有的任何路由慣例；不要發明新的頂層結構。
2. **極易執行。** UI 原型可透過專案工作執行器（task runner）中的單一指令啟動：`pnpm <name>`、`python <path>`、`bun <path>` 等。邏輯展示品則是使用者點兩下即可開啟的單一 HTML 檔案。無論何種方式，啟動時都無需思考。
3. **預設無持續性。** 狀態保留於記憶體中。持續性是原型正在_查驗_的事物，而非它應該依賴的事物。若問題明確涉及資料庫，請使用暫存資料庫或帶有明確 "PROTOTYPE, wipe me" 名稱的本機檔案。
4. **略過修飾潤色。** 不寫測試，除了讓原型_可執行_所需的錯誤處理之外不做其他處理，不建立抽象。重點在於快速學習。
5. **浮現狀態。** 在每個動作（邏輯）之後或每次切換變體（UI）時，輸出或算圖出完整的相關狀態，讓使用者能看清變更了什麼。
6. **完成後予以擷取。** 將任何經驗證的決策整合進真實程式碼中，然後將原型本身擷取為**一手資料來源**：將其提交至脫離 main 的拋棄式分支，並在實作 issue 上留下指向該分支的上下文指標。同時在 issue 或提交中擷取答案（結論與其所解決的問題）。main 分支僅保留經驗證的決策。
