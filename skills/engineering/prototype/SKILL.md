# 原型

原型是**回答問題的一次性程式碼**。問題決定了形狀。

## 選擇分支

識別要回答的問題 — 從使用者的提示詞、周圍的程式碼，或者在使用者在場時詢問：

- **「這個邏輯 / 狀態模型感覺正確嗎？」** → [LOGIC.md](LOGIC.md)。建構單一可共享的 HTML 檔案 — 自由操作按鈕外加分頁式引導流程 — 將狀態機推向紙面上難以推理的情況，且非開發人員亦可操作。
- **「這個看起來應該像什麼？」** → [UI.md](UI.md)。在單一路線上產生多個截然不同的 UI 變體，可透過 URL 搜尋參數與浮動底部列進行切換。

這兩個分支產生的產物截然不同 — 弄錯這一點會浪費整個原型。如果問題確實存在歧義且無法聯絡到使用者，請預設為與周圍程式碼更匹配的分支（後端模組 → 邏輯；頁面或元件 → UI），並在原型頂部說明假設。

## 適用於兩者的規則

1. **從第一天起就是一次性的，且明確標註。** 將原型程式碼放置在實際使用的位置附近（緊鄰其原型設計的模組或頁面），使上下文清晰明瞭 — 但對其命名，使隨意閱讀的人能看出它是原型而非正式環境程式碼。對於一次性 UI 路線，請遵循專案現有的路由慣例；不要發明新的頂層結構。
2. **執行極為簡單。** UI 原型從專案任務執行器中的單一命令啟動 — `pnpm <name>`、`python <path>`、`bun <path>` 等。邏輯 Demo 是使用者雙擊的單一 HTML 檔案。無論哪種方式，啟動都不需要思考。
3. **預設無持久性。** 狀態存在於記憶體中。持久性是原型正在_檢查_的事物，而不是它應該依賴的事物。如果問題明確涉及資料庫，請使用草稿 DB 或帶有清晰「PROTOTYPE — wipe me」名稱的本地檔案。
4. **跳過潤飾。** 沒有測試，除了讓原型_可執行_之外沒有錯誤處理，沒有抽象。重點是快速學到東西。
5. **浮現狀態。** 在每次動作（邏輯）之後或每次變體切換（UI）時，列印或渲染完整的相關狀態，以便使用者看到改變了什麼。
6. **完成時進行擷取。** 將任何經過驗證的決策併入真實程式碼中，然後將原型本身作為**主要來源**進行擷取：將其提交至脫離 main 的一次性分支，並在實作議題上留下該分支的上下文指標。同時在議題或提交中擷取答案 — 結論與其解決的問題。main 分支僅保留經過驗證的決策。
