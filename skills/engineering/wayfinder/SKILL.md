一個粗略的想法到了 — 對於單一 Agent 會話而言太龐大，且包覆在迷霧中：從這裡通往**目的地**的道路尚未可見。尋路是為了找到那條道路，而不是盲目衝向目的地。此技能將該道路在儲存庫的議題追蹤器上繪製為**共享地圖**，然後處理其**決策票券** — 其解決方案是決策而非要執行的建構切片的問題 — 一次處理一個，直到路線變為清晰。

目的地因工作而異，且對其進行命名是繪製的第一步 — 它塑造了每張票券。它可能是移交並迭代的規格、在規劃開始前鎖定的決策，或像資料結構遷移那樣的就地變更。該地圖是領域無關的 — 工程工作、課程內容，凡符合形狀者皆可。

## 規劃，而非執行

Wayfinder 預設為**規劃**：每張票券解決一個決策，當道路清晰時地圖即告完成 — 在某人去執行該事物之前沒有殘留需要決定的內容。直接做工作的衝動通常意味著您已抵達地圖邊緣且是時候進行移交的訊號。工作可以在其 **Notes** 中覆寫此點 — 將執行帶入地圖本身 — 但在缺乏該說明的狀況下，請產生決策而非交付成果。

## 按名稱引用

每張地圖與票券都是一個議題，因此它有一個**名稱** — 其標題。在人類閱讀的所有內容中 — 敘述、地圖的 Decisions-so-far — 都按該名稱引用它，絕不使用單純的 id、數字或 slug。一整牆的 `#42, #43, #44` 是難以閱讀的；名稱一目了然。id 與 URL 並未消失 — 名稱包裹著其連結 — 但它們騎在名稱的_內部_，絕不代表名稱。

## 地圖

地圖是此儲存庫議題追蹤器上標有 `wayfinder:map` 的單一議題 — 規範的產物。其票券是該地圖的子議題。

地圖是一個**索引**，而非儲存庫。它列出所做出的決策並指向持有其細節的票券；決策恰好存在於一個地方 — 其票券 — 因此地圖絕不重述它，只提供摘要與連結。

**地圖、其子票券、阻塞關係與邊界查詢實際存放於何處，取決於議題追蹤器。** 應該已有人提供議題追蹤器給您。如果沒有，請告知使用者執行 `/setup-matt-pocock-skills`。請查閱追蹤器文件中的「尋路操作」章節，了解_此_儲存庫如何表達這些內容。如果未提供任何追蹤器，則預設使用本機 Markdown 追蹤器。

### 票券

每張票券都是地圖的**子議題**；追蹤器的議題 id 就是其身份。其主體為問題，大小調整為單一 100K token 的 Agent 會話：

```markdown
## Question

<此票券解決的決策或調查>
```

每張票券都帶有 `wayfinder:<type>` 標籤 — 為 `research`、`prototype`、`grilling`、`task` 之一（參見 [Ticket Types](#ticket-types)）。

會話在任何工作之前，**最先**透過將票券指派給主導地圖的開發人員來**認領**該票券，使併發會話跳過它。該受派者_即為_認領：開啟且未指派的票券即為未認領。

阻塞使用追蹤器的**原生**依賴關係 — 這至關重要，因為它會在追蹤器自己的 UI 中以_視覺化_方式渲染邊界，使人類無需開啟地圖就能看到有什麼可被領取。僅當缺乏原生阻塞的追蹤器才會備用為主體慣例。當阻塞某票券的每張票券都關閉時，該票券即為**解除阻塞**；**邊界（frontier）**是開啟、未阻塞且未認領的子項目 — 已知領域的邊緣。

答案不是主體的一部分 — 它在解決時被記錄（參見 [Work through the map](#work-through-the-map)）。在解決票券時建立的資產會從議題進行連結，而非貼入。

## 票券型態

每張票券要麼是 **HITL** — 人類在環路中，與代表自己發言的人類*一同*工作 — 要麼是 **AFK**，由 Agent 單獨驅動。HITL 票券僅透過該即時交流解決；Agent 絕不能代表人類的一方（自己回答自己問題的盤問 Agent 破壞了這一點）。

- **Research（研究）**（AFK）：閱讀文件、第三方 API 或知識庫等本機資源，以找出決策所需的事實。由呼叫 Skill 工具並使用「research」的子 Agent 解決。當需要目前工作目錄以外的知識時使用。
- **Prototype（原型）**（HITL）：製作可供回應的低成本、粗略且具體的產物，以提高討論的具體程度 — 例如大綱、粗略方案、樣板或 UI／邏輯程式碼，並呼叫 Skill 工具使用「prototype」。將原型連結為資產。當「應該長什麼樣子」或「應該如何運作」是關鍵問題時使用。
- **Grilling（盤問）**（HITL）：對話。預設情況。務必呼叫 Skill 工具兩次，分別使用「grilling」和「domain-modeling」。
- **Task（任務）**（HITL 或 AFK）：在做出_決策_前必須發生的手動工作 — 沒有需要決定、原型製作或研究的事物，但討論被阻塞直到其完成。註冊服務以便評估其 API、佈署存取權限、移動資料以便了解其形狀。這是唯一一種_執行_而非決定的型態 — 且它透過解除決策阻塞而非交付目的地來賺得其位置。Agent 在可能之處單獨驅動它（AFK）；否則它會交給人類一份精準的檢核表（HITL）。當工作完成時解決；答案會記錄所做的工作以及後續票券所依賴的任何結果事實（憑證位置、新 URL、列數）。

## 戰爭迷霧

地圖是_故意_不完整的：不要繪製您尚未看到的內容。在實時票券之外躺著**戰爭迷霧** — 您能知道即將到來但尚未能確定的決策與調查的模糊視野，因為它們懸掛在仍未解決的問題上。解決一張票券會清除其前面的迷霧，將現在可明確規格的任何內容晉升為新鮮票券 — 一次一個，直到通往目的地的道路變為清晰且沒有票券殘留。

地圖的 **尚未規格化** 章節是寫下該模糊視野的地方：懷疑的問題、稍後要重新造訪的區域。它是通往目的地的未發現邊界 — 此處的每一件事物都在範疇內，只是還不夠銳利到能開立票券。在視野允許的情況下撰寫得盡可能寬鬆或完整；它也兼作閱讀該工作走向的協作者的路標。

**迷霧還是票券？** 測試在於您現在能否精準陳述該問題 — _而不是_您現在能否回答它。

- **開立票券的時機：** 當問題已經很銳利時 — 即使它受阻塞且您現在還不能對其採取行動。
- **尚未規格化 的時機：** 當您還無法那麼銳利地表述它時。不要將迷霧預先切片為票券大小的碎片：它比票券更粗糙，且一旦邊界抵達，一個區域可能會晉升為好幾張票券，或者一張也沒有。

**尚未規格化** 不包含已決定的內容（目前的決策）、已經是實時票券的內容，以及範疇之外的內容（下一章節）。

## 範疇之外

迷霧只會朝向目的地聚集。目的地固定了範疇，因此超越它的工作即為**範疇之外** — 它不是迷霧，也不屬於 **尚未規格化**。它在地圖上獲得其專屬的 **範疇之外** 章節：您有意識地將其排除在_此_工作之外的工作。是範疇而非銳利度使其降落於此。

範疇之外的工作絕不畢業 — 邊界在目的地處停止 — 因此只有在目的地被重新繪製時它才會返回，且屆時是作為新鮮工作，而非恢復。

將某事物劃定為範疇之外是一種劃定範疇的行為，而非路線上的步驟。當一張已經存在的票券結果位於目的地之外時 — 在繪製時誤劃入範疇，或由解決方案暴露出來 — **關閉它**（已關閉的票券明確離開邊界），並在 **範疇之外** 章節留下單行：摘要加上為何其在範疇之外，並連結已關閉的票券。它不包含在 **目前的決策** 中，後者記錄實際走過的路線 — 範疇邊界不是其上的步驟。

## 呼叫

兩種模式。無論哪種方式，**每個會話解決的票券切勿超過一張** — research 票券除外。

### 繪製地圖

使用者帶著粗略的想法呼叫。

1. **命名目的地。** 呼叫 Skill 工具兩次，分別使用「grilling」與「domain-modeling」，以釐清這張地圖要尋找到的是什麼 — 規格、決策或變更。目的地會確定範疇，因此必須先定案。
2. **繪製邊界。** 再次進行盤問，這次採**廣度優先**：橫跨整個空間展開而非深鑽任何單一線索，浮現開啟的決策與現在可採取的最初步驟。**如果這未浮現任何迷霧** — 通往目的地的道路已經清晰，整個旅程小到足以放入一個會話中 — 您不需要地圖。停止並詢問使用者希望如何進行。
3. **建立地圖**（標籤 `wayfinder:map`）：填入 目的地 與 備註，目前的決策 為空，將迷霧勾勒至 **尚未規格化** 中。
4. 將您現在能明確規格的票券**建立**為地圖的子議題 — 然後在**第二輪**中連接阻塞邊界（議題在能相互引用前需要 id）。連接會將它們分類為邊界與受阻塞；您還無法明確規格的所有內容都留在迷霧中 — 即 **尚未規格化** 章節。
5. **啟動研究子 Agent。** 對於您剛建立的每張 `research` 票券，啟動一個呼叫 Skill 工具並使用「research」的子 Agent，平行解決這些票券；將其發現記錄在暫存的 `research/<name>` 分支上，並從票券提供內容指標。
6. 停止 — 繪製是一個會話的工作；它不手動解決任何事物。

### 逐步處理地圖

使用者帶著地圖（URL 或號碼）進行呼叫。票券是**可選的** — 沒有票券時，由您挑選下一個決策，而非使用者。

1. 載入**地圖** — 低解析度檢視，而非每張票券的主體。
2. 選擇票券。如果使用者具名指明一張，使用它。否則按順序取第一張邊界票券。**認領它**：在進行任何工作之前將其指派給您自己。
3. 解決它 — **視需要放大檢視**：按需取得任何相關或已關閉票券的完整主體；針對 `## 備註` 區塊所列出的技能呼叫 Skill 工具。如有疑問，呼叫 Skill 工具兩次，分別使用「grilling」與「domain-modeling」。
4. 記錄解決方案：將答案發布為**解決留言**，**關閉**該議題，並在地圖的 目前的決策 **附加上下文指標**。
5. 新增新浮現的票券（先建立再連接）；將答案使其變為可明確規格的任何迷霧進行晉升，從 **尚未規格化** 中清除每個已晉升的區域，使其僅作為新票券存在。如果答案揭示了一張票券 — 這張或其他張 — 位於目的地之外，**將其劃定為範疇之外**，而不是在路線上解決它。如果該決策使地圖的其他部分失效，請更新或刪除那些票券。

使用者可能會平行執行解除阻塞的票券，因此請預期其他會話會同時編輯追蹤器。
