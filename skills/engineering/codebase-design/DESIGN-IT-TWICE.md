# 設計兩次（Design It Twice）

當使用者想要為所選的深化候選項探索替代介面時，使用此平行子 Agent 模式。基於「設計兩次」（Ousterhout）— 您的第一個構想不太可能是最好的。

使用 [SKILL.md](SKILL.md) 中的詞彙 — **模組（module）**、**介面（interface）**、**接縫（seam）**、**轉接器（adapter）**、**槓桿（leverage）**。

## 流程

### 1. 構建問題空間

在衍生子 Agent 之前，為所選的候選項撰寫針對使用者的問題空間說明：

- 任何新介面都需要滿足的約束
- 它將依賴的依賴項，以及它們屬於哪個類別（參見 [DEEPENING.md](DEEPENING.md)）
- 用於落實約束的粗略範例程式碼草圖 — 不是提案，只是讓約束變得具體的一種方式

將此內容展示給使用者，然後立即進行步驟 2。當子 Agent 平行工作時，使用者可進行閱讀與思考。

### 2. 衍生子 Agent

平行衍生 3 個以上的子 Agent。每個子 Agent 必須為深化後的模組產生**截然不同**的介面。

使用單獨的技術簡報提示每個子 Agent（檔案路徑、耦合細節、來自 [DEEPENING.md](DEEPENING.md) 的依賴項類別、位於接縫背後的內容）。該簡報獨立於步驟 1 中針對使用者的問題空間說明。給予每個 Agent 不同的設計約束：

- Agent 1："最小化介面 — 目標最多 1–3 個進入點。最大化每個進入點的槓桿作用。"
- Agent 2："最大化彈性 — 支援多種使用情境與擴充。"
- Agent 3："針對最常見的呼叫者進行最佳化 — 使預設情況變得極為簡單。"
- Agent 4（如適用）："圍繞跨接縫依賴項的埠與轉接器進行設計。"

在簡報中包含 [SKILL.md](SKILL.md) 詞彙與 CONTEXT.md 詞彙，以便每個子 Agent 的命名與架構語言及專案的領域語言保持一致。

每個子 Agent 輸出：

1. 介面（型別、方法、參數 — 外加不變性、順序、錯誤模式）
2. 顯示呼叫者如何使用它的使用範例
3. 實作在接縫背後隱藏了什麼
4. 依賴項策略與轉接器（參見 [DEEPENING.md](DEEPENING.md)）
5. 權衡 — 槓桿作用高之處、槓桿作用薄弱之處

### 3. 呈現與比較

按順序呈現設計，以便使用者吸收每一個設計，然後用散文比較它們。依據**深度**（介面處的槓桿作用）、**局部性**（變更集中的地方）以及**接縫位置**進行對比。

比較之後，給出您自己的建議：您認為哪個設計最強大以及原因。如果來自不同設計的元素能很好地組合，請提出混合方案。請具備明確見解 — 使用者想要的是強有力的解讀，而不是選單。
