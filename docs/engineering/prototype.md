## 功能說明

`prototype` 撰寫**用以回答問題的一次性程式碼**：這個狀態模型感覺對嗎、或是這個畫面應該長成什麼樣。問題先行並決定了後續所有內容的形態；回答錯誤問題的原型純粹是浪費，無論它看起來有多好。

「一次性」是對程式碼*如何撰寫*的限制，而非銷毀它的承諾。沒有測試、除了能讓程式碼執行之外沒有額外的錯誤處理、沒有抽象層、沒有持續性儲存，因為這些都無助於你了解你想探究的核心問題。保留下來的是融入真實程式碼中的答案，以及停留在脫離 main 的獨立分支上的原型本身，作為該答案來源的證據。

## 何時使用

輸入 `/prototype`，或者當任務適合時 [agent](https://www.aihero.dev/ai-coding-dictionary/agent) 會自動調用它。

當你遇到無法透過討論敲定的問題時請立即使用它：邊界情況多到無法在腦中全盤掌握的狀態機、只有並排看到三種版本才能具體想像的畫面。[盤問（Grilling）](https://www.aihero.dev/ai-coding-dictionary/grilling) session 往往正是因為這些問題而膨脹：agent 換句話說、你進行猜測，範圍隨之擴大以填補不確定性。停止盤問，建構一次性版本，觀察它，然後以一句話回答。反之，如果已建構的事物行為異常且你想知道原因，請使用 [diagnosing-bugs](https://aihero.dev/skills-diagnosing-bugs)；原型探索的是要建構什麼，而不是已建構的事物為何損壞。

你也可能在非主動選擇的情況下來到此處。[wayfinder](https://aihero.dev/skills-wayfinder) 會在其地圖上建立 `prototype` 決策 [tickets](https://www.aihero.dev/ai-coding-dictionary/ticket)，而處理其中一張票券正是本技能的職責。

## 兩個分支

問題決定了分支，而分支會產出截然不同的產物：

- **「這套邏輯／狀態模型感覺對嗎？」**：**單一可分享的 HTML 檔案**。一個獨立且無需建構與伺服器的頁面，任何人按兩下即可開啟。它包含一個在每次點擊後重新渲染的具名狀態面板、可依任意順序嘗試該模型的自由操作按鈕、以及分頁式的**引導式演練（guided walkthroughs）**（每個分頁一個情境，下方附有依序按下的按鈕）。所有內容皆以領域語言標註，因此你可以將其交給設計師、PM 或領域專家，讓他們親自體驗該模型。頁面背後的邏輯是一個微型的純模組（reducer、狀態機、一組函式），與 DOM 完全脫鉤，因此驗證後的版本可以直接移植到真實程式碼中。
- **「這個應該長成什麼樣？」**：在單一路由上提供數個**截然不同**的使用者介面變體，可透過浮動底列與 `?variant=` URL 參數進行切換。變體之間的差異必須在於結構而非色彩；三個微調過的卡片網格只是桌布，算不上原型。它們盡可能在真實頁面內渲染，對應真實資料與真實密度，因為在真空環境中評估的變體看起來永遠都不錯。

兩者皆將狀態儲存在記憶體中，啟動時無需深思熟慮，且在每一步後向你展示完整狀態。一旦你發現自己正在將其強化加固（新增測試、連接真實資料庫、針對未來可能需要的情境進行通用化），你就已經停止了原型設計。

## 原型即主要來源

完成的原型會留下兩樣事物，且它們會前往不同的位置。

**答案**（結論加上其所敲定的問題）會被持久記錄：commit 訊息、ADR、實作 issue。這正是 main 分支所保留的內容，融入真實程式碼之中。

**原型**是該答案來源的可執行證據，且不會被刪除。它也不屬於 main：該處沒有需要維護的內容且它腐化得很快。因此它會被 commit 到脫離 main 的一次性 `prototype/<name>` 分支上，永不合併，並在實作 issue 上留下指向該分支的 [context 指標](https://www.aihero.dev/ai-coding-dictionary/context-pointer)。Main 分支保持乾淨；探索成果則保持可尋找且可由接手後續工作的人重新執行。

## 常見問題

**等等，原型不是應該被刪除嗎？**
現在不用了。過去確實是：建構它、保留答案、丟棄程式碼。對此最強烈的反對從來不是因為速度，而是：*下一個 [session](https://www.aihero.dev/ai-coding-dictionary/session) 接手工作的人是誰，他們有什麼依據可以著手？* 原型的散文摘要會喪失其具說服力的核心本質。因此原型現在被視為[主要來源（primary source）](https://www.aihero.dev/ai-coding-dictionary/primary-source)：它落在脫離 main 的 `prototype/<name>` 分支上，且實作 issue 指向它。改變的是程式碼存放的位置，而非紀律；它依然永不合併至 main。

**它以前會建構終端機應用程式。這功能去哪了？**
邏輯分支現在改為輸出單一可分享的 HTML 檔案。終端機應用程式只能由複製了儲存庫並安裝了執行環境的人來操作，這恰好排除了原型最需要其意見的人：設計師、PM、以及了解該狀態模型代表何種意義的領域專家。單一獨立、按兩下即可開啟且透過電子郵件寄送也不會損壞的檔案，任何人都可以操作。底層的純邏輯模組保持不變，且依然是可以直接移植至真實程式碼的部分。

**當我本該進行實作時，agent 卻叫我執行 `/prototype`。**
這是已知情況，且屬於命名問題。`prototype` 是一個通用且具吸引力的字眼，對於不熟悉流程的 agent 來說，一旦票券存在，它讀起來就像是「顯而易見的下一步」，因此即使設計已經在對話中完全敲定，它仍會被指名推薦。如果你已經知道要建構什麼，下一步是依票券執行 `/implement`。只有在特定的設計問題確實尚未解決且討論無法解決時，才需要調用原型。

**在建構任何正式環境功能之前，我應該為整個應用程式建立原型嗎（例如向潛在客戶進行展示）？**
那是借用了此技能名稱的不同產物。此處的原型僅限於單一問題，而「整個應用程式是什麼？」並非單一問題。完整應用程式的原型沒有天然的停止點，因此它會憑藉慣性變成正式應用程式：清理階段從未發生，而在原型規則下撰寫的程式碼（無測試、無錯誤處理）最終暴露在使用者眼前。若你需要銷售展示，請特意將其建構為 demo 並明確聲明這完全不是正式環境程式碼。若你需要解決設計問題，請將其縮減至該問題本身。

**我該如何在獨立的 session 中執行它？**
原型存在於自身的目錄中，並產生大量你不想留在提出問題之討論串中的 [context](https://www.aihero.dev/ai-coding-dictionary/context)，因此請在其他地方執行它並僅帶回答案。[handoff](https://aihero.dev/skills-handoff) 是雙向溝通的橋樑。

**這難道不是消耗 tokens 最快的方式嗎？**
確實可能如此，如果你為本可透過討論回答的問題建立原型，或者放任一個原型蔓延跨越整個功能。重要的比較不是 tokens 與零消耗的比對；而是 [tokens](https://www.aihero.dev/ai-coding-dictionary/token) 與建構出錯誤狀態模型並在正式環境呼叫端使用後才發現問題的比對。將問題範圍縮窄並縮短執行時間，支出就能維持在合理比例。

## 運作正常的指標

- 你能用一句話說出原型所要回答的問題，且它被寫在展示的最上方，而不僅僅留在你的腦海中。
- 不懂程式碼的人也能操作該邏輯展示。他們開啟檔案、在演練分頁中按下按鈕，並用自己的話描述所見的內容。
- 有人說「等等，這不應該是可能的」或「咦，我原本以為是 X」。那是*想法*上的錯誤，而這正是原型的全部意義。
- 使用者介面變體在版面配置與資訊層級上有所不同，而不僅僅是色彩與文案，且你收到的回饋是「B 的頁首搭配 C 的側邊欄」。
- 問題在單次作業中得到解答。若一天後你仍在建構它，說明問題過於龐大；請將其拆分。
- 結束時，main 分支包含決策且不含任何原型程式碼，而實作 issue 指向仍保存該原型的分支。

## 適用位置

`prototype` 是一個**隨時可調用的獨立技能**：你進入它以解決單一設計問題，隨後退出，且它也是其他技能運作時的底層機制。

其最大的取用者是 [wayfinder](https://aihero.dev/skills-wayfinder)。Wayfinder 地圖由**決策票券**組成，而 `prototype` 是票券四種類型之一：當阻擋問題是「這應該長成什麼樣」或「它的行為應該如何」且任何討論都無法解決時所使用的類型。Wayfinder 透過打造具體事物供人反應，提升了模糊討論的逼真度，而本技能正是建構該具體事物的方式。原型票券透過答案得以解決，且原型會作為資產連結至地圖中。

其他相鄰技能位於其上游與下游。[grill-me](https://aihero.dev/skills-grill-me) 與 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 回答可被盤問的問題；不可被盤問的問題則來到此處，且單行答案會回傳給訪談。在下游，經過驗證的狀態模型或使用者介面方向會成為 [to-spec](https://aihero.dev/skills-to-spec) 的敲定輸入，後者可以直接行內嵌入原型產出的富決策程式碼片段，而非以散文進行描述。至於其他任何情境，[ask-matt](https://aihero.dev/skills-ask-matt) 會在整個集合中為你進行路由。
