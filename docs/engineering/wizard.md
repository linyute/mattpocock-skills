## 它的功能

`wizard` 產生一個互動式 Bash 指令碼，逐步引導人類完成手動程序：串接第三方服務、執行單次遷移、將專案從狀態 A 轉移至狀態 B。它開啟每個 URL、說明該點擊與複製什麼、擷取回傳的內容，並將其寫入 `.env` 檔案與 GitHub Actions secrets 中。

由 [agent](https://www.aihero.dev/ai-coding-dictionary/agent) 編寫該指令碼；它絕不會執行它。由你在自己的機器上執行。因此 wizard 不是一份供你遵循的指示清單；它是一個驅動程序並保存狀態的程式，而你的任務則是點擊、貼上並按下 Enter。

## 何時使用它

你可以輸入 `/wizard`，agent 也可以自行使用它。當它遇到你必須執行的步驟時（它無法鑄造的金鑰、無法點擊的儀表板），它會為你建構一個 wizard，而不是將指示寫入對話中隨後被捲動淹沒。

當阻礙你的下一步是前往儀表板操作時，請使用它：

| 情境 | Wizard 的作用 |
| --- | --- |
| 新開發人員在應用程式啟動前需要設定六個服務 | 依序開啟每個儀表板、擷取金鑰、將其寫入 `.env` 與 CI |
| 單次遷移需要按特定順序切換開關 | 將不可逆的步驟安排在確認關卡之後 |
| 專案必須一次性地從狀態 A 轉移到狀態 B | 引導完成轉換並回報無法完成的事項 |
| 你正準備將這些步驟寫入 README | 改為編寫可執行的版本，不會那麼容易悄悄過期 |

不要使用它來*決定*建構什麼；為此，[grill-with-docs](https://aihero.dev/skills-grill-with-docs) 與 [to-spec](https://aihero.dev/skills-to-spec) 才是合適的工具。

## 先決條件

產生指令碼無需任何先決條件。它所編寫的 wizard 在 Bash 上執行，並在階段設定 GitHub secret 或 variable 時使用 `gh`。如果缺少 `gh` 或未經認證，該階段會變成警告，且結尾摘要會告訴你該手動設定什麼，而不是使執行失敗。

## 階段 (Stages)

一個**階段 (stage)** 是單一螢幕上的單一焦點任務。指令碼會在各階段之間清除終端機畫面，因此超出螢幕的階段會遺失捲動走的部分。你依相依性順序編寫階段並設定 `TOTAL_STAGES`，這會驅動進度顯示。

劃定範圍在編寫任何一行之前進行。[skill](https://www.aihero.dev/ai-coding-dictionary/skill) 會讀取儲存庫而不是毫無頭緒地提問：`.env*`、`docker-compose*`、框架設定，以及 `.github/workflows/` 中的每個 `secrets.*` / `vars.*` 參照：每個都是 wizard 必須產出的值。接著它向你展示排序後的階段清單以供確認，只有在那之後才會將每個階段對應至人類遵循的精確路徑（「儀表板 → 開發人員 → API 金鑰 → 顯示測試金鑰 → 複製」）。在它不知道當前 UI 的地方，它會詢問你或查閱文件，而不是捏造點擊步驟。

對於每個擷取到的值，範圍劃定會確定其存放位置：

| 目的地 | 何時 |
| --- | --- |
| 僅限 `.env` | 本地開發需要，CI 不需要 |
| GitHub secret | CI 需要讀取它，且它具敏感性 |
| GitHub variable | CI 需要讀取它，且它是公開的 |
| `.env` 與 secret 兩者 | 本地開發與 CI 皆需要 |
| 無處存放 | 該階段是純操作：切換開關、升級方案 |

## 範本已解決使用者體驗問題

該[範本 (template)](https://github.com/mattpocock/skills/blob/main/skills/engineering/wizard/template.sh) 提供了完整體驗：包含剩餘時間的進度、確認關卡、包含 WSL 在內的跨平台 URL 開啟、機密隱藏輸入、等冪 `.env` 更新、`gh secret` / `gh variable` 寫入，以及它必須跳過之所有內容的結尾摘要。`STAGES` 標記之上的所有內容都是固定的函式庫，在每個 wizard 中都是相同的，絕不需要手動編輯。一致性就是重點。你的工作只是劃定程序的範圍並編寫其階段。

編寫 wizard 的 agent 絕不會端對端執行它，因為它會開啟瀏覽器並等待人工輸入。它改為進行靜態驗證：`bash -n`、可用的 `shellcheck`，以及追蹤每個值是否如範圍劃定所言存放在該放的位置，每個 `set_secret` 名稱都與 CI 中真實的 `secrets.*` 參照相符。請相應調整你的預期：第一次執行屬於你，而該次執行就是測試。

## 預設為拋棄式

| 你擁有的內容 | 如何處置該指令碼 |
| --- | --- |
| 單次遷移、個人設定、永不重複的轉移 | 將其儲存至 scratch 或 `scripts/` 路徑，執行它，然後刪除它 |

## 常見問題

**我的 API 金鑰會進入模型上下文嗎？**

不會。Agent 編寫指令碼；它不會執行它。你自己執行該指令碼，它透過終端機隱藏輸入擷取金鑰，並直接將其寫入 `.env` 或 `gh secret`。Wizard 是一個 CLI，模型並未與其連線。一個注意事項：這適用於 wizard 在執行階段擷取的值。如果你在劃定程序範圍時將金鑰貼到對話中，它就會像其他貼上的文字一樣進入[上下文 (context)](https://www.aihero.dev/ai-coding-dictionary/context)。

**我可以倒回去修正打錯的值嗎？**

執行中不行。沒有返回按鈕：各階段向前進行，在階段 3 給出錯誤答案意味著按 Ctrl-C 並重新執行。重新執行在設計上成本很低：任何已經寫入 `.env` 的值都會作為預設值提供，因此你只需對正確的階段按 Enter，只重新輸入錯誤的那一個。這在發布當週就被提出且此後未曾關閉：「太棒了！但有一點，有辦法倒回去更正已輸入的內容嗎？」

有一個相關且未解決的 bug。在 `ask` 提示中按方向鍵會插入 `^[[D` / `^[[C` 而非移動游標，因為提示使用的是 `read -r` 而非 Readline（[issue #741](https://github.com/mattpocock/skills/issues/741)）。退格鍵有效；方向鍵無效。請倒退刪除到錯誤處，而非將游標移進去。

**它知道我已經設定了什麼嗎？**

部分知道，但比發布時的反響所設想的少。它在提問前會讀取儲存庫（你的 `.env` 檔案、`docker-compose`、框架設定、CI 中的 `secrets.*` 參照），因此它的範圍限定在真正缺少的值，而不是像 README 那樣從零開始。它不會做的是檢查第三方服務。如果金鑰存在於你的 `.env` 中，wizard 會將其作為預設值提供，按 Enter 即可保留；如果你已經建立了 Stripe 帳戶但從未儲存金鑰，wizard 仍會引導你前往儀表板取得它。

**它在工作流程中位於何處，在 grilling 和規格之後嗎？**

沒有特定位置。它是一個獨立工具，而非鏈條中的步驟。常見的猜測是 `/grill-with-docs → /to-spec → /wizard`，該順序沒有問題，但觸發條件是出現手動程序，這可能發生在任何時刻：在開始之前、建構中途，或交付很久之後。它也可以作為探索工具：在投入工作之前，範圍劃定會浮現任務的隱藏先決條件，例如你未曾想過的三個 API 金鑰。

**它在 Claude Code 之外能運作嗎？**

產出物無條件可以：它是一個純 Bash 指令碼，它不在乎是哪個 [harness](https://www.aihero.dev/ai-coding-dictionary/harness) 產生了它。該 skill 本身是由模型呼叫的，因此隨處可見：在 Claude Code 中輸入 `/wizard` 或在 Codex 中輸入 `$wizard`，或者直接描述你卡住的設定。由模型呼叫也使其避開了 [#693](https://github.com/mattpocock/skills/issues/693)，在該問題中，Claude 的桌面與網頁介面會從[模型](https://www.aihero.dev/ai-coding-dictionary/model)清單中丟棄*使用者呼叫 (user-invoked)*的 skill，並將其回報為未安裝。

**這以前不是使用者呼叫的嗎？**

過去是。現在改為模型呼叫，因此當 agent 遇到你必須採取的步驟時，會主動使用它。你以前能做的任何事情都沒有停止運作：模型呼叫*增加*了 agent 的觸及範圍，絕不剝奪你的權利，因此 `/wizard` 的行為與過去完全相同。改變的是它所淘汰的失敗模式：agent 在建構中途遇到憑證阻礙，並在對話中傾倒六個編號步驟供你手動遵循。

**它以前在 `in-progress/` 中：現在在哪裡？**

自 v1.2 起位於 `engineering/`。它從測試分類中畢業，現在隨外掛程式一起發布，因此它會與其餘晉升的技能組一起提供，無需個別安裝。它在畢業後的行為沒有改變。

## 若運作正常，會符合以下情況

- 在任何指令碼存在之前，向你展示排序後的階段清單以及每個階段產出的值，並要求你確認。
- 在要求提供該頁面的值之前，每個 URL 都已被開啟。絕不會要求你貼上尚未派你去獲取的內容。
- 機密皆以隱藏方式輸入。任何敏感資訊都不會回顯到你的捲動歷史中。
- 每個階段適合單一螢幕。你仍需要的任何內容都不會捲動消失。
- Ctrl-C 並重新執行會從你中斷的地方接續，將已儲存的值作為預設值提供。
- 最終螢幕列出它寫入的內容，並個別列出它無法完成且必須由你手動完成的事項。

## 它的定位

`wizard` 是一個隨時可用的獨立工具，位於自動化停止且必須由人工點擊的交界處。其最近的鄰居是 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills)，因為兩者的存在都是為了讓儲存庫進入工作狀態：前者設定這套技能組，而 `wizard` 則為其他所有事物產生設定路徑。它也與 [implement](https://aihero.dev/skills-implement) 搭配：當建構交付了一項需要憑證或手動切換的功能時，wizard 是完成人類部分工作的方式。當你不確定當前適合哪項 skill 時，[ask-matt](https://aihero.dev/skills-ask-matt) 會為你引導。
