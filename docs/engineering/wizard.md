## 它的功能

`wizard` 會產生一個互動式 Bash 腳本，引導人類按部就班地完成手動程序 — 設定第三方服務、執行一次性遷移、將專案從狀態 A 移動至狀態 B。它會開啟每個 URL，說明要點擊與複製的內容，擷取傳回的內容，並將其寫入 `.env` 檔案和 GitHub Actions Secrets 中。

[Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 會撰寫腳本；但它絕不會執行它。您需要在自己的電腦上執行它。因此，wizard 不是您要遵循的指令列表 — 它是一個驅動程序並保持狀態的程式，而您的工作就是點擊、貼上並按 Enter。

## 何時使用它

您可以輸入 `/wizard`，且 Agent 也可以主動使用它。當它遇到您必須採取的步驟時 — 它無法發行的密鑰、它無法點擊的儀表板 — 它會為您建構一個 wizard，而不是將指令寫入聊天中（在那裡指令會向上捲動消失）。

當下一個阻礙您的事物是前往儀表板操作時，請使用它：

| 情況 | Wizard 所做的事 |
| --- | --- |
| 新開發人員需要在應用程式啟動前設定六個服務 | 依序開啟每個儀表板，擷取密鑰，並將其寫入 `.env` 和 CI |
| 一次性遷移需要按特定順序切換開關 | 將不可逆的步驟排列在確認閘道之後 |
| 專案必須有一次從狀態 A 移動到狀態 B | 走過過渡過程並回報其無法做到的內容 |
| 您即將把這些步驟寫入 README | 改為撰寫可執行版本，這不會輕易過時腐朽 |

不要使用它來*決定*要建構什麼；為此，[grill-with-docs](https://aihero.dev/skills-grill-with-docs) 和 [to-spec](https://aihero.dev/skills-to-spec) 才是工具。

## 先決條件

要產生一個 wizard 完全不需要先決條件。它所寫的 wizard 在 Bash 上執行，並在階段設定 GitHub Secret 或變數時使用 `gh`。如果缺少 `gh` 或未經過身份驗證，該階段會變成警告，且結尾的摘要會告訴您手動設定什麼，而不是使執行失敗。

## 階段

**階段**是單一螢幕上的專注任務。腳本會在階段之間清除終端機，因此超出螢幕的階段會失去向上捲動消失的部分。您按照依賴順序編撰階段並設定 `TOTAL_STAGES`，這會驅動進度顯示。

範疇界定在撰寫程式碼行之前發生。[Skill](https://www.aihero.dev/ai-coding-dictionary/skill) 會讀取儲存庫而不是冰冷地提問：`.env*`、`docker-compose*`、框架設定，以及 `.github/workflows/` 中對 `secrets.*` / `vars.*` 的每個引用 — 其中每一個都是 wizard 必須產生的值。然後它會向您顯示排序好的階段列表以供確認，且僅在此之後才會將每個階段映射到人類遵循的精確路徑（「儀表板 → 開發人員 → API 密鑰 → 揭示測試密鑰 → 複製」）。在它不知道當前 UI 的地方，它會詢問您或查看文件，而不是捏造點擊。

對於每個擷取到的值，範疇界定決定了其落腳處：

| 目的地 | 時機 |
| --- | --- |
| 僅 `.env` | 本機開發需要，CI 不需要 |
| GitHub secret | CI 會讀取且屬於敏感資料 |
| GitHub variable | CI 會讀取且屬於公開資料 |
| `.env` 和 Secret 兩者 | 本機開發和 CI 都需要 |
| 無處落腳 | 階段是純粹的操作 — 開關切換、計畫升級 |

## 範本已經解決了 UX

[範本](https://github.com/mattpocock/skills/blob/main/skills/engineering/wizard/template.sh) 附帶了完整的體驗：帶有剩餘時間的進度顯示、確認閘道、包含 WSL 在內的跨平台 URL 開啟、隱藏式 Secret 輸入、冪等的 `.env` 插入更新 (upsert)、`gh secret` / `gh variable` 寫入，以及所有它必須跳過內容的結尾摘要。`STAGES` 標記之上的所有內容都是固定的函式庫，在每個 wizard 中完全相同，且絕不手動編輯。一致性才是重點。您的工作只是界定程序的範疇並編撰其階段。

撰寫 wizard 的 Agent 絕不會端到端地執行它，因為它會開啟瀏覽器並等待人類輸入。它改為靜態驗證：`bash -n`、在可用時使用 `shellcheck`，以及追蹤每個值是否落在範疇界定所說的地方，其中每個 `set_secret` 名稱都與 CI 中真實的 `secrets.*` 引用相比對。據此設定您的期望 — 第一次執行是您的，且該執行就是測試。

## 預設為暫時性的

| 您擁有的內容 | 對腳本要做的事 |
| --- | --- |
| 一次性遷移、個人設定、您絕不會重複的過渡 | 將其儲存到草稿或 `scripts/` 路徑，執行它，然後刪除它 |
| 儲存庫上的下一個人也需要的設定路徑 | Commit 它並從 README 進行連結，這樣他們會執行腳本，而不是重新詢問 Agent |

## 常見問題

**我的 API 密鑰最終會進入模型的內容嗎？**

不會。Agent 撰寫腳本；它不會執行它。您自己執行腳本，它透過隱藏的終端機輸入擷取密鑰並將其直接寫入 `.env` 或 `gh secret`。Wizard 是一個 CLI，且模型未連接到它。一個警告：這適用於 wizard 在執行階段擷取的值。如果您在界定程序範疇時將密鑰貼入聊天中，它就會像任何其他貼上的文字一樣進入 [內容](https://www.aihero.dev/ai-coding-dictionary/context)。

**我可以返回並修正我輸錯的值嗎？**

在執行中途不行。沒有返回按鈕 — 階段向前執行，第 3 階段的錯誤答案意味著按 Ctrl-C 並重新執行。按設計重新執行成本很低：任何已經寫入 `.env` 的值都會作為預設值重新提供，因此您只需在正確的階段按 Enter，並僅重新輸入錯誤的階段。這在發布週就被提出且此後一直未關閉：「太棒了！不過有一件事 — 有沒有辦法返回並修正您輸入的內容？」

有一個相關的開放 Bug。在 `ask` 提示中的方向鍵會插入 `^[[D` / `^[[C` 而不是移動游標，因為提示使用了 `read -r` 而不是 Readline ([Issue #741](https://github.com/mattpocock/skills/issues/741))。Backspace 有效；方向鍵無效。請退格刪除到錯誤處，而不是將游標移入其中。

**它知道我已經設定了什麼嗎？**

部分知道，且比發布反應所假設的要少。它在詢問前會讀取儲存庫 — 您的 `.env` 檔案、`docker-compose`、框架設定、CI 中的 `secrets.*` 引用 — 因此它的範疇限定於真正缺失的值，而不是像 README 那樣從零開始。它不做的是檢查第三方服務。如果 `.env` 中存在密鑰，wizard 會將其重新提供且 Enter 會保留它；如果您已經建立了 Stripe 帳戶但從未儲存密鑰，wizard 仍會傳送您到儀表板以取得它。

**它在工作流程中處於什麼位置 — 在盤問和規格之後？**

沒有特定位置。它是一個獨立的工具，而不是鏈條中的步驟。常見的推測是 `/grill-with-docs → /to-spec → /wizard`，且該順序很好，但觸發條件是出現手動程序，這可能發生在任何時間點：在您開始之前、建構中途，或在交付後很久。它也可以作為一種探索工具 — 在您承諾工作之前，範疇界定會呈現任務隱藏的先決條件（例如您沒有想到的三個 API 密鑰）。

**它是否能在 Claude Code 之外運作？**

產物無條件可以：它是一個純 Bash 腳本，不在乎是什麼 [Harness](https://www.aihero.dev/ai-coding-dictionary/harness) 產生了它。Skill 本身是由模型呼叫的，因此它列在所有地方 — 在 Claude Code 中輸入 `/wizard` 或在 Codex 中輸入 `$wizard`，或者只需描述您卡住的設定即可。由模型呼叫也使其擺脫了 [#693](https://github.com/mattpocock/skills/issues/693)，其中 Claude 的桌面和 Web 表面將*使用者呼叫的* Skill 從 [模型](https://www.aihero.dev/ai-coding-dictionary/model) 的列表中捨棄，並回報它們未安裝。

**這以前不是使用者呼叫的嗎？**

是的。它現在是模型呼叫的，因此當 Agent 遇到您必須採取的步驟時，它會主動使用它。您以前能做的事情沒有任何停止運作 — 模型呼叫*增加了* Agent 的存取範圍，它絕不會移除您的存取權，因此 `/wizard` 的行為與以前完全相同。改變的是它退役的失敗模式：Agent 在建構中途碰到憑證牆，並在聊天中傾倒六個編號步驟供您手動跟隨。

**它以前在 `in-progress/` 中 — 現在在哪裡？**

自 v1.2 起在 `engineering/`。它從 Beta 區中晉升，現在在外掛程式中發布，因此它與普及集合的其餘部分一起抵達，而不是需要個別安裝。它在晉升時行為沒有改變。

## 運作良好的指標

- 在任何腳本存在之前，向您展示排序好的階段列表以及每個階段產生的值，並要求您確認。
- 在要求該頁面的值之前開啟每個 URL。絕不會要求您貼上未傳送您去擷取的事物。
- Secret 盲打輸入。沒有敏感內容會列印到您的向上捲動歷史中。
- 每個階段適合一個螢幕。您仍然需要的內容沒有向上捲動消失。
- Ctrl-C 並重新執行會接續您中斷的地方，提供已經儲存的值作為預設值。
- 最終螢幕列出它寫入的內容，並單獨列出它無法做到的內容以及您必須手動完成的內容。

## 適用位置

`wizard` 是一個隨時可使用的獨立工具，位於自動化停止而人類必須點擊的界線上。它最近的鄰居是 [setup-matt-pocock-skills](https://aihero.dev/skills-setup-matt-pocock-skills)，因為兩者的存在都是為了讓儲存庫進入工作狀態 — 那一個設定此 Skill 集合，而 `wizard` 為其他所有內容產生設定路徑。它還可以與 [implement](https://aihero.dev/skills-implement) 搭配：當建構落地了需要憑證或手動切換的功能時，wizard 就是人類那一半完成的方式。當您不確定哪個 Skill 適合該時刻時，[ask-matt](https://aihero.dev/skills-ask-matt) 會為您引導路線。
