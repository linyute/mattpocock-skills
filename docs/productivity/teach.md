## 它的功能

`teach` 會將您執行它的目錄轉變為常設的教學工作區，並在跨越許多 [階段作業](https://www.aihero.dev/ai-coding-dictionary/session) 的情況下，以簡短自包含的 HTML 課程向您教授一個主題。

它不會從 [模型](https://www.aihero.dev/ai-coding-dictionary/model) 已經知道的內容進行教學。[參數化知識](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge) 被視為不可信：在教授之前，它會去尋找高信任度的資源，將其記錄在 `RESOURCES.md` 中，並在每一課內部進行引用。另一個結構性事實是它是 **[有狀態的](https://www.aihero.dev/ai-coding-dictionary/stateful)** — 使命、資源、課程以及您已學習內容的記錄全作為檔案存在於目錄中，因此下一個階段作業會接續這些檔案，而不是接續上一次對話留下的任何內容。

## 何時使用它

您可透過輸入 `/teach` 來呼叫此功能 — [Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不會主動使用它。

當學習就是專案本身時使用它：一門語言、一個框架、您剛加入的程式碼庫、瑜伽、Shader、一項認證。它不是用於順帶解釋一次的概念的工具。

| 您想要的內容 | 使用工具 |
| --- | --- |
| 在數週內學習一個主題，並累積階段作業 | `teach` |
| 在您已處於的階段作業中解釋一個想法 | 直接在該階段作業中詢問 |
| Agent 的最新訊息因未精確傳達而重新陳述 | [wait-what](https://aihero.dev/skills-wait-what) |
| 磨練您現有的思考，而不是獲取新材料 | [grill-me](https://aihero.dev/skills-grill-me) |
| 後台 Agent 讀取 [原始來源](https://www.aihero.dev/ai-coding-dictionary/primary-source) 並留給您引用的文件 | [research](https://aihero.dev/skills-research) |
| 學習盤問中途出現的內容，而不偏離 [盤問](https://www.aihero.dev/ai-coding-dictionary/grilling) | [handoff](https://aihero.dev/skills-handoff) 出去到教學工作區，然後在該處執行 `teach` |

## 先決條件

`teach` 會建構一個目錄而不是產生一個檔案，且 Skill 假設每個工作區有一個使命 — 因此請在您樂意讓渡給單一主題的地方執行它。讓它遠離您正在工作的專案：推薦的歸宿是一個單獨的儲存庫，而不是全域的 `~/.learnings/` 資料夾或工作專案本身。專門的儲存庫還使課程可被 Commit，這是團隊共享課程的方式。

在該目錄中累積的內容：

| 路徑 | 包含內容 |
| --- | --- |
| `MISSION.md` | 您學習此內容的原因。其他一切都懸掛在其上；如果缺失，`teach` 做的第一件事就是訪談您直到完成該檔案 |
| `RESOURCES.md` | 它用來教學的審查過的來源，分為 Knowledge 和 Wisdom (社群) |
| `lessons/*.html` | 編號的課程 — 教學的主要單元 |
| `reference/*.html` | 壓縮的速查表、演算法、詞彙表：您實際返回查看的文件 |
| `learning-records/*.md` | ADR 風格的筆記，記錄您可證明已學習的內容，用於決定接下來要教什麼 |
| `assets/*` | 可重複使用的元件 — 首先是共享樣式表 — 使課程看起來像是一門課程 |
| `NOTES.md` | 您聲明的教學偏好 |

關於該列表的兩個誠實筆記。詞彙表適合大多數主題，但 Skill 發布了一個 `GLOSSARY-FORMAT.md`，`SKILL.md` 不再連結到它，因此除非您主動要求，否則您只會得到一個 ([Issue #559](https://github.com/mattpocock/skills/issues/559))。且工作區並不總是建立在您預期的地方 — 在您建立長課程之前，請先參閱下面的第一個問題。

## 儲存強度，而非流利度

用於思考的詞彙是**儲存強度**：長期記憶保留，相對於**流利度**（即在您閱讀時感覺像掌握一樣的當下回想，一週後即消失）。`teach` 透過理想的困難（檢索練習、間隔、交錯）來建立前者。知識放在第一位，在該處困難是敵人，因為它吞噬了您為了理解而需要的即時記憶力；然後透過緊密的回饋迴圈來鍛鍊 Skill，在該處困難是工具。

有兩件事引導您被傳授的內容。**使命** — 您想要這個內容的具體真實世界理由 — 奠定了每一課的基礎；沒有它，課程會偏向抽象且沒有任何內容決定接下來的內容。根據使命和學習記錄，`teach` 在您的**近側發展區**內部挑選下一課：足夠挑戰以需要付出努力，但又不會領先太遠以至於停止變得可學習。

這也是為什麼 Skill 進行反駁而不是討好的原因。需要**智慧**（真實世界的判斷）的問題會得到一個嘗試性的答案，然後指向您可以測試它的社群。測驗是閘道，而不是形式：一名使用者回報說說了「非常感謝」後被告知演練仍然在進行中。

## 課程、參考與元件

**課程**是一個自包含的 HTML 檔案，足夠短以在一次作業中完成，與使命掛鉤，給予一個切實的收穫。它引用其來源，推薦一個主要來源供您自己去閱讀，並連結到同級課程和參考文件。

值得了解的分工：課程很少被重新造訪，參考文件則會。因此課程的壓縮精華 — 語法表、演算法、姿勢序列、詞彙表 — 屬於 `reference/`，而不是埋在介紹它的課程中。

課程是由 `assets/` 中的**元件**建構而成的：樣式表、測驗小工具、模擬器、圖表輔助工具。重複使用是預設選項。Agent 在編撰課程之前讀取 `assets/` 並從現有內容建構，且第二課可以使用任何新的內容都被寫成元件而不是內聯。共享樣式表是每個工作區贏得的第一個元件；它是阻止輸出變成一堆一次性內容的要素。

## 常見問題

**它將檔案放在哪裡？我的檔案最終落在 `~/.claude/skills` 中。**
一個真實且開放的 Bug ([#377](https://github.com/mattpocock/skills/issues/377))。`SKILL.md` 同時將 `./` 用於兩個不同的根目錄：`./MISSION-FORMAT.md` 及其同級檔案確實位於安裝 Skill 中 `SKILL.md` 的旁邊，而 `./lessons/`、`./reference/`、`./learning-records/` 和 `./assets/` 旨在位於您的目錄中。按 Skill 安裝目錄解析第一種類型的 Agent 也會在那裡解析第二種類型，並將您的課程寫入 Skill 資料夾中。在建立課程之前檢查第一課落在哪裡，並在開始時明確命名目錄，而不是依賴於「當前目錄」被理解。

**我留在同一個階段作業中，還是每課開始一個新階段作業？**
這三種方法都可行 — 留在同一個階段作業中、在新的階段作業中重新呼叫 `/teach`，或者在相同的資料夾中開啟新的階段作業。每一課都是其自己的呼叫。資料夾是連續性，而不是對話。常見的做法是在工作區中開啟全新的階段作業並說 `/teach next lesson for <topic>`。

**我如何知道它沒有教我虛構的內容？**
僅憑 Skill 的文字您無法知道。您閱讀原始來源。`teach` 不夠可靠無法不加檢查地信任，且沒有建立在 LLM 上的 Skill 是可靠的。接地機制 — `RESOURCES.md`、每一課中的引用、每一課推薦一個原始來源 — 存在是為了讓驗證變便宜，而不是為了消除驗證的需要。失敗不是假設性的：一名學習 2x2 魔術方塊的使用者獲得了無法解決它的虛構移動序列。針對此類情況的診斷檢查清單是模型、框架 (harness)、努力 (effort) — 以及來源是什麼。在具有精確標記法的程序領域中風險最高，而在輸出可立即驗證的領域（如您可以執行的程式碼）中風險最低。

**正確的測驗答案總是第一個選項。**
多個人在 Sonnet、Opus 和 GLM 上予以證實，且仍未修復。`SKILL.md` 現在要求每個答案都必須是相同的字數，這消除了一個不同的特徵（以前正確答案是唯一獲得充分推論的答案），但對位置沒有說明。一名貢獻者測試了針對位置的指令層級修復，並回報正確答案在 9 課的 33 次中仍然落在選項 A 33 次 ([#335](https://github.com/mattpocock/skills/issues/335))，這指向 `assets/` 中隨機播放的測驗元件才是真正的修復，而不是更好的字眼。在發布之前，將答案位置視為無意義。您的 `assets/` 目錄是您的，因此要求在轉譯時隨機播放的元件是合法的本機修復。

**它假設我已經知道某些事情，並使用了它從未定義的術語。**
最常見的實質性抱怨。沒有評估步驟：`teach` 從使命和學習記錄中推導您的水平，而在第一階段作業中沒有學習記錄。一名在 wayfinder 管線內部執行它的使用者直言不諱地指出 —「它從未進行盤問來確定我的起點，因此它對我已經知道的內容做了很多假設。」另一名使用者回報課程依賴於未定義的術語，以及針對其硬體定制的課程涵蓋了硬體可以做什麼，但從未說過它不能做什麼。有兩件事有所幫助：在第一條訊息中陳述您先前的知識和您的缺口，並在課程錯過時大聲修正水平，因為修正會成為學習記錄並引導下一課。明確的知識評估步驟是一個常設的功能請求 ([#725](https://github.com/mattpocock/skills/issues/725))，而不是發布的行為。

**它是否會進行間隔重複，且它是否知道何時停止教學？**
第一個否定，第二個不可靠。間隔和交錯是課程設計所依據的原則，但沒有任何內容排程複習，且沒有 Anki 或日曆整合 — 兩者都是重複的要求。相關的缺口是退出條件：正如一名使用者所言，`teach`「擅長製作下一課，但不擅長知道何時停止並切換到複習或實際練習。」如果您想要複習或演練而不是新材料，請主動要求；Skill 不會自己提出切換建議。

**它只對程式碼有用嗎？**
不是，且非程式碼用途是記錄中較大的部分：韓語、日語正式語域、鋼琴、吉他、桌遊設計、OpenSCAD、電影情節、Azure 和 CCNA 認證、大學考試，以及 8 歲和 10 歲的孩子獲得關於密室逃脫和火蠑螈的可列印書籍。Skill 中沒有任何內容是專門針對程式設計的 — 使命、資源、近側發展區和演練在任何領域中的工作方式都相同。在程式碼內部，最強大的回報用途不是從頭開始學習一門語言，而是在陌生的程式碼庫或新團隊的堆疊中定向。

**我應該用哪個模型執行它？**
沒有規範答案，且回報的差異很大。據回報，較高的 [推理努力](https://www.aihero.dev/ai-coding-dictionary/effort) 能產生比中等設定明顯更好的課程。一名使用者透過帶有 Codex 的 Copilot CLI 執行相同的 Skill，獲得了單個 30 行的 HTML 卡片，而 Claude Code 產生了完整的課程。它可以在 Claude Cowork 中未經修改地執行，前提是您的組織允許在那裡新增 Skill。如果課程產出很薄，請在重新撰寫提示之前變更模型、[框架](https://www.aihero.dev/ai-coding-dictionary/harness) 或努力。

## 運作良好的指標

- 在空目錄中它做的第一件事是就您為什麼想要這個訪問您，而不是產生一課。
- `RESOURCES.md` 在課程之前填滿，且每一課都命名了一個值得自己閱讀的主要來源。
- 課程中的主張帶有外部連結。沒有引用的課程是 Skill 憑記憶教學。
- 一課需要一次作業，並讓您能夠做到以前無法做到的事情。
- 在資料夾中開啟全新的階段作業並說 "next lesson" 會繼續課程而不是重新開始。
- `learning-records/` 增長，且課程停止重新教授您已經證明的內容。
- 課程看起來像是一門課程 — 它們連結 `assets/` 中的樣式表，而不是各自攜帶自己的樣式表。
- 需要判斷的問題會讓您指向論壇、Subreddit 或課程，而不僅僅是一個答案。

## 適用位置

`teach` 是一個**隨時可使用的獨立工具**。它不是建構鏈中的步驟，且不與工程流程共享產物；它擁有自己的目錄，並在該主題持續的時間內生活在那裡。

它一個真正的鄰居是 [handoff](https://aihero.dev/skills-handoff)，透過 Matt 命名的組合來回答「如果我被盤問我不理解的事情該怎麼辦？」：不要停止盤問來學習 — `/handoff` 出去到教學工作區，在那裡使用 `/teach` 學習它，然後回去並接續您中斷的地方。附近的替代方案是 [research](https://aihero.dev/skills-research)，適用於您想要的是引用的文件而不是課程和保留。當您不確定哪個 Skill 或流程適合時，[ask-matt](https://aihero.dev/skills-ask-matt) 會在整個集合中為您引導路線。
