## 功能說明

`teach` 會將你執行它的目錄轉變為常設的教學工作區，並透過許多簡短且自成一體的 HTML 課程，跨多個[工作階段](https://www.aihero.dev/ai-coding-dictionary/session)向你傳授單一主題。

它不會僅根據[模型](https://www.aihero.dev/ai-coding-dictionary/model)已知的知識進行教學。[參數化知識](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)被視為不可信任的：在教學之前，它會主動尋找高信任度的資源，將其記錄在 `RESOURCES.md` 中，並在每個課程中引用它們。另一個架構上的事實是它具備[狀態](https://www.aihero.dev/ai-coding-dictionary/stateful)：使命、資源、課程以及你學到的內容記錄都以檔案形式存在該目錄中，因此下一個工作階段會從這些檔案繼續，而不是依賴上次對話留下的殘餘記憶。

## 何時使用它

你可以透過輸入 `/teach` 來呼叫它；[Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不會主動使用它。

當「學習」本身就是專案時使用它：一種程式語言、一個框架、你剛加入的程式碼庫、瑜伽、著色器、一項認證。它不是用來隨口解釋一次概念的工具。

| 你的需求 | 應使用的工具 |
| --- | --- |
| 在數週內學習一個主題，並累積各個工作階段的進度 | `teach` |
| 在你已身處的工作階段中解釋單一想法 | 直接在該工作階段中提問 |
| 因為沒聽懂而需要 Agent 重新換個方式解釋上一則訊息 | [wait-what](https://aihero.dev/skills-wait-what) |
| 磨練你已有的思維，而不是獲取新材料 | [grill-me](https://aihero.dev/skills-grill-me) |
| 需要背景 Agent 閱讀[第一手來源](https://www.aihero.dev/ai-coding-dictionary/primary-source)並留下一份附有引用的文件 | [research](https://aihero.dev/skills-research) |
| 學習盤問過程中出現的事物，且不中斷[盤問](https://www.aihero.dev/ai-coding-dictionary/grilling)流程 | [交接](https://aihero.dev/skills-handoff)至教學工作區，然後在那裡使用 `teach` |

## 先決條件

`teach` 會建構一個目錄而不是產出單一檔案，且該技能預設每個工作區只有一項使命，因此請在你可以專門用於單一主題的地方執行它。請將它保留在工作專案之外：建議放在獨立的儲存庫中，而不是全域的 `~/.learnings/` 資料夾或工作專案本身。專用儲存庫也使課程得以被 commit，這正是各團隊分享課程的方式。

在該目錄中累積的內容：

| 路徑 | 內容說明 |
| --- | --- |
| `MISSION.md` | 你學習這個主題的原因。其他所有內容都依附於它；如果缺少此檔案，`teach` 的第一步就是訪談你直到建立此檔案為止 |
| `RESOURCES.md` | 它用於教學的經過審查的來源，分為知識（Knowledge）與智慧（Wisdom，社群） |
| `lessons/*.html` | 編號課程：教學的主要單元 |
| `reference/*.html` | 精簡的速查表、演算法、術語表：你實際會反覆查閱的文件 |
| `learning-records/*.md` | ADR 風格的筆記，記錄你已展現掌握的知識，用於決定下一步要教授什麼 |
| `assets/*` | 可重複使用的元件，從共享樣式表開始，使課程看起來像是一門完整的系列課程 |
| `NOTES.md` | 你設定的教學偏好 |

關於該清單有兩點誠實的提醒：術語表適用於大多數主題，但此技能隨附的 `GLOSSARY-FORMAT.md` 已不再被 `SKILL.md` 連結，因此只有在主動要求時你才會得到術語表（[issue #559](https://github.com/mattpocock/skills/issues/559)）。此外，工作區不一定會建立在你預期的地方，因此在基於它建構長篇課程之前，請先參閱下方的第一個問題。

## 儲存強度，而非流暢度

思考的核心概念是**儲存強度**：長期記憶保留能力，相對於**流暢度**（當下閱讀時感覺自己掌握了、但一週後就忘光的暫時回憶）。`teach` 透過有益的困難（desirable difficulty）來建構前者：提取練習、間隔重複、交錯學習。知識排在第一位，在此階段困難是敵人，因為它會消耗你理解所需的工作記憶體；隨後技能透過緊密的反饋循環進行演練，在此階段困難則是工具。

有兩件事引導著你所學的內容。**使命**（你在真實世界中需要它的具體理由）是每節課程的根基；沒有它，課程就會變得抽象，而且無法決定下一步要學什麼。根據使命與學習記錄，`teach` 會在你的**近側發展區間**（zone of proximal development）內挑選下一節課程：具有足夠挑戰性而需要付出努力，但又不會太超前而變得難以吸收。

這也是為什麼該技能會提出反詰而不是盲目順從。需要**智慧**（真實世界判斷力）的問題會得到一個嘗試性的回答，然後指向你可以驗證該答案的社群。測驗是一個關卡，而不是走形式：有使用者回報說在說了「非常感謝」之後，被告知演練仍在繼續進行中。

## 課程、參考資料與元件

一節**課程**是一個自成一體的 HTML 檔案，簡短到可以在單次閱讀中完成、緊扣使命，並帶來一個實質的收穫。它引用其來源、推薦一份值得親自閱讀的第一手來源，並連結到同系列的相鄰課程與參考文件。

值得了解的劃分：課程很少被重新翻閱，而參考文件則會。因此，課程的精煉精華（語法表、演算法、動作序列、術語表）應該放在 `reference/` 中，而不是埋在介紹它的課程裡。

課程是由 `assets/` 中的**元件**建構而成：樣式表、測驗小工具、模擬器、圖表輔助工具。重複使用是預設做法。Agent 在撰寫課程之前會讀取 `assets/` 並基於已有內容進行建構，而第二節課程可能用到的任何新內容都會寫成元件而非內嵌處理。共享樣式表是每個工作區獲得的第一個元件；它能避免產出變成一堆一次性的雜亂檔案。

## 常見問題

**它把檔案放在哪裡？我的檔案最後出現在 `~/.claude/skills`。**
一個真實且未解決的錯誤（[#377](https://github.com/mattpocock/skills/issues/377)）。`SKILL.md` 同時將 `./` 用於兩個不同的根目錄：`./MISSION-FORMAT.md` 及其同級檔案確實位於已安裝技能中的 `SKILL.md` 旁，而 `./lessons/`、`./reference/`、`./learning-records/` 和 `./assets/` 則本應位於你的目錄中。將第一種類型解析為技能安裝目錄的 Agent，也會繼續將第二種類型解析到那裡，並將你的課程寫入技能資料夾中。在基於它建構更多內容之前，請先檢查第一節課程存放在哪裡，並在開始時明確指定目錄，而不是依賴對「目前目錄」的默契理解。

**我應該留在同一個工作階段中，還是每節課都啟動一個新工作階段？**
這三種方法都可行：保留在同一個工作階段中、在新工作階段中重新呼叫 `/teach`，或者在同一個資料夾中開啟新工作階段。每節課都是獨立的呼叫。資料夾才是延續性的載體，而非對話本身。常見做法是在工作區中開啟全新工作階段並輸入 `/teach next lesson for <topic>`。

**我如何知道它傳授的不是自行捏造的內容？**
單憑此技能的說法，你無法確定。你需要閱讀第一手來源。`teach` 還不夠可靠，不能在未經查證的情況下完全信任，事實上任何基於 LLM 建構的技能都是如此。錨定機制（`RESOURCES.md`、每節課中的引用、每節課推薦的一份第一手來源）的存在是為了降低驗證成本，而不是消除驗證的必要。這種失敗並非假設：一位學習二階魔術方塊的使用者被提供了無法還原的虛構轉法步驟。針對此類情況的診斷檢查清單包括模型、測試載具、推論深度以及來源為何。在具有精確符號的程序性領域中風險最高，而在產出可立即驗證的領域（例如可執行的程式碼）風險最低。

**測驗的正確答案永遠是第一個選項。**
這一點已經被多人在 Sonnet、Opus 和 GLM 上證實，且仍未修復。`SKILL.md` 現在要求每個答案的字數必須相同，這消除了另一個破綻（以前正確答案通常是唯一具有完整推導說明的選項），但對選項位置沒有做任何規定。一位貢獻者測試了針對位置的指令層級修復，並回報在九節課程中，正確答案依然 33 次全落在選項 A（[#335](https://github.com/mattpocock/skills/issues/335)），這表明在 `assets/` 中加入洗牌測驗元件才是真正的解決之道，而非改進提示詞措辭。在此問題正式解決前，請將答案位置視為毫無意義。你的 `assets/` 目錄由你自由修改，因此要求在轉譯時自動洗牌的元件是合理的地方修復方案。

**它預設我已經知道某些知識，並使用了從未定義過的術語。**
這是最常見的實質抱怨。因為沒有評估步驟：`teach` 是從使命和學習記錄中推斷你的程度，而在第一個工作階段中根本沒有學習記錄。一位在 wayfinder 流程中執行它的使用者直白地說：「它從未進行盤問來確定我的起點，因此對我已知的知識做了很多假設。」另一位使用者則回報課程依賴未定義的術語，以及專為其硬體量身定製的課程只介紹了硬體能做什麼，卻從未說明它不能做什麼。有兩件事能改善這一點：在第一則訊息中說明你的既有知識與盲點，並在課程難度失焦時明確糾正，因為糾正會轉化為學習記錄並引導下一節課。明確的知識評估步驟是一項長期存在的功能請求（[#725](https://github.com/mattpocock/skills/issues/725)），而非現有功能。

**它是否提供間隔重複功能？它知道何時該停止教學嗎？**
第一點為否，第二點則無法可靠做到。間隔與交錯是課程設計所依據的原則，但沒有任何排程複習機制，也沒有 Anki 或行事曆整合；這兩者都是經常被提出的需求。相關的盲點是退出條件：正如一位使用者所言，`teach`「擅長製作下一節課，但不擅長知道何時該停下來並切換到複習或實際演練。」如果你想要複習或演練而不是新教材，請主動提出要求；此技能不會自行建議切換。

**它只對程式碼有用嗎？**
並非如此，非程式碼領域的使用反而佔了記錄的大多數：韓文、日文敬語、鋼琴、吉他、桌遊設計、OpenSCAD、電影情節、Azure 與 CCNA 認證、大學考試，以及八歲與十歲孩童獲得關於密室逃脫和火蠑螈的可列印書籍。此技能中的一切都非程式設計專屬：使命、資源、近側發展區間與演練在任何領域的運作方式都相同。在程式碼領域內，最被推崇的用途不是從頭學習一門語言，而是在不熟悉的程式碼庫或新團隊的技術堆疊中快速熟悉定向。

**我應該使用哪種模型來執行它？**
沒有標準答案，而且回報的差異很大。據回報，較高的[推論深度](https://www.aihero.dev/ai-coding-dictionary/effort)產出的課程明顯優於中等設定。一位使用者透過使用 Codex 的 Copilot CLI 執行相同的技能，只得到一張 30 行的 HTML card，而 Claude Code 則產出了一節完整的課程。在你的機構允許新增技能的前提下，它也可以原封不動地在 Claude Cowork 中執行。如果產出的課程內容單薄，在重寫提示詞之前，請先更換模型、[測試載具](https://www.aihero.dev/ai-coding-dictionary/harness)或推論深度。

## 運作良好的跡象

- 在空目錄中，它的第一件事是訪談你為什麼需要這個，而不是產出課程。
- `RESOURCES.md` 在課程產生前就已填滿，且每節課程都會列出一份值得親自閱讀的第一手來源。
- 課程中的主張帶有外部連結。沒有引用的課程代表該技能是在憑記憶教學。
- 一節課程只需單次閱讀時間，並讓你能做到先前做不到的一件事。
- 在該資料夾中開啟全新工作階段並輸入「下一課」會延續課程，而不是重新開始。
- `learning-records/` 不斷增長，課程不再重複教授你已經展現掌握的內容。
- 各節課程看起來風格一致：它們連結至 `assets/` 中的樣式表，而不是各自攜帶自己的樣式。
- 需要主觀判斷的問題會引導你前往論壇、Reddit 看板或課堂，而不僅僅是給出一個答案。

## 適用定位

`teach` 是一個**隨時可用的獨立工具**。它不是建構鏈中的一個步驟，也不會與工程流程共享任何成品（artifact）；它擁有自己的目錄，並在該主題存續期間一直存在於該目錄中。

它唯一的近鄰是 [handoff](https://aihero.dev/skills-handoff)，透過 Matt 針對「如果我被盤問我所不理解的事物該怎麼辦？」所提出的組合解法：不要為了學習而中斷盤問：使用 `/handoff` 到教學工作區，在那裡使用 `/teach` 進行學習，然後返回並接續中斷之處。相近的替代方案是 [research](https://aihero.dev/skills-research)，適用於你想要一份附帶引用的文件而不是課程與長期記憶留存時。當你不確定哪種技能或流程適合時，[ask-matt](https://aihero.dev/skills-ask-matt) 會在整套工具中為你引導。
