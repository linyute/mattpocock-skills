## 它的功能

`grill-me` 會取得一個**粗略的想法**並對您進行訪談，直到您可以對其作出承諾。您不需要在開始時就有一個精雕細琢的計畫 — 產生一個計畫正是該 [階段作業](https://www.aihero.dev/ai-coding-dictionary/session) 的目的。它以**輪數**進行提問：每一輪都是整個**前沿** — 即其先決條件您已經定稿的每一個問題 — 因此絕不會向您詢問取決於尚未聽到的答案的問題。

它是**[無狀態的](https://www.aihero.dev/ai-coding-dictionary/stateless)**。它不撰寫檔案，也不會留下工作區。它留下的唯一東西是您腦海中對該想法更銳利的版本。

## 何時使用它

您可透過輸入 `/grill-me` 來呼叫此功能 — [Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不會主動使用它。在**全新的對話**中啟動它，而不是建立在您已經讓 Agent 撰寫好的計畫之上。

只要您有一個值得認真對待的想法 — 功能、產品方向、商業決策、一篇寫作 — 且在您弄清楚它包含什麼之前很久，就可以使用它。模糊不是等待的理由；它正是該階段作業所吞噬的東西。如果您已經可以精確地指定該事物，則不需要對其進行盤問。

您需要三種盤問技能中的哪一種取決於您面前的內容：

- **任何地點的任何事物** — `grill-me`。它不需要儲存庫且不撰寫檔案，主題也不必是程式碼。
- **要對齊的程式碼庫** — [grill-with-docs](https://aihero.dev/skills-grill-with-docs)。相同的訪談，但是**[有狀態的](https://www.aihero.dev/ai-coding-dictionary/stateful)**：它會讀取您的程式碼，並將其學到的內容保留在 `CONTEXT.md` 和 ADR 中。
- **對於單個階段作業而言太龐大** — [wayfinder](https://aihero.dev/skills-wayfinder)。它將工作繪製為地圖並在其中執行盤問階段作業。

關閉 [計畫模式](https://www.aihero.dev/ai-coding-dictionary/agent-mode)。計畫模式會使 Agent 急於產生計畫，這與保持在詢問狀態正好相反。

## 這是一場對話，而不是一場訪談

Skill 會提出問題，但**您**擁有範疇。這是人們忽略的部分，它將一個將想法轉化為決策的階段作業，與一個產生自信廢話的階段作業區分開來。

失敗模式是**被動性** — 對 40 個問題回答「同意、同意、同意」，並得出一個 Agent 撰寫而您點頭同意的計畫。這感覺很有成效，因為它很長。實際上沒有做任何決定，且結果帶有未經考驗的確定性。

主動意味著主導。對低於您所需精確度的問題進行反駁。在範疇偏離時指出。回答「我不知道」並且是認真的。此 Skill 旨在協助工程師，而不是取代工程師：產出的品質取決於您回答的品質，而不是提出的問題數量。

相反的錯誤是真實存在但更罕見的 — 在訪談中停留太久以至於永遠無法接觸程式碼。

## 可盤問與不可盤問

有些問題可以透過討論來回答。其他則不行，再多的盤問也無法帶您到達目的地。

「一個長表單還是三個頁面？」以及「這種互動感覺如何？」是**不可盤問的** — 它們需要可以反應的對象。當您遇到時，請停止盤問。使用 [prototype](https://aihero.dev/skills-prototype) 建構一次性拋棄的版本，查看它，然後回來在一行內回答。

討論不可盤問的問題是階段作業膨脹的原因。Agent 不斷重新表述，您不斷猜測，而範疇擴大以填補不確定性。

## 運作良好的指標

- 您對某些內容表示不同意。沒有您反駁的階段作業就是您不需要的階段作業。
- 問題以幾輪的形式出現，而不是長期的滴水式呈現，且後續輪數明顯建立在您先前說過的內容之上。
- 您最終到達了一個意想不到的地方，因為一個問題呈現了您一直在隱性做出的決策。
- 最後，您可以向不在場的人辯護每個選擇。

## 常見問題

**我應該預期會有多少個問題，以及我如何知道何時結束？**
計算輪數，而不是問題數量。跨越 4 輪的 46 個問題是一個普通的階段作業。當前沿為空時結束 — 每個分支都被造訪，沒有留下默默假設的內容。

**它問了我兩百個問題。出了什麼問題？**
通常是範疇太大。首先要求 Agent 將工作拆解為較小的部分，然後盤問每一個部分。非常長的階段作業也會漂移到 **[笨拙區域](https://www.aihero.dev/ai-coding-dictionary/smart-zone)**，在該處 [內容視窗](https://www.aihero.dev/ai-coding-dictionary/context-window) 足夠滿以至於問題變差。

**我可以回到一次一個問題嗎？**
可以。將此新增至您的全域 `CLAUDE.md`：

```
When grilling, ask one question at a time.
```

**如果我真的不知道答案怎麼辦？**
直接說。「我不知道」是一個真實的答案，而您無法回答的問題通常是建立原型 (prototype) 的信號，而不是猜測的信號。

**在撰寫規格之前我需要啟動新的階段作業嗎？**
不需要。階段作業的價值在於您剛剛建構的 [內容](https://www.aihero.dev/ai-coding-dictionary/context)。將同一個對話直接移交給 [to-spec](https://aihero.dev/skills-to-spec)。

**模型重要嗎？**
比大多數 Skill 更重要。盤問依賴於 [模型](https://www.aihero.dev/ai-coding-dictionary/model) 本身對系統如何損壞的敏銳度，因此請給它最好的模型。實作主要跟隨內容，可以容忍較便宜的模型。

## 適用位置

`grill-me` 是一個**隨處可對任何事物執行的獨立工具**。無狀態使其具有可攜性：沒有儲存庫、沒有工作區、沒有設定，也沒有假設該想法甚至與軟體有關。人們將其指向商業決策、寫作、下一步該做什麼 — 任何無法在他們腦海中靜止的事物。

這種可攜性是與 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 的全部差異，後者執行相同的訪談，但會讀取程式碼庫以進行對齊，並將其學到的內容記錄為 `CONTEXT.md` 和 ADR。兩者都基於 [grilling](https://aihero.dev/skills-grilling) 原語；`grill-me` 是使用者呼叫的大門，不隨身攜帶任何內容。

如果您盤問的內容確實證明是軟體，您可以將同一個對話移交給 [to-spec](https://aihero.dev/skills-to-spec) 並繼續進入建構流程 — 這是一個選項，而不是該 Skill 的核心目的。當您不確定哪個流程適合時，[ask-matt](https://aihero.dev/skills-ask-matt) 會為您引導路線。
