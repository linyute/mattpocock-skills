## 功能說明

`grill-me` 接受一個**粗略的想法**，並對你進行訪談，直到你能對其做出承諾。你不需要擬定完整的計畫就能開始：產生計畫正是[工作階段](https://www.aihero.dev/ai-coding-dictionary/session)的目的。它按**輪次**提問：每一輪都是完整的**邊界**（每個其先決條件你都已經確定的問題），因此絕不會向你提出取決於它尚未聽到的答案的問題。

它是**[無狀態的](https://www.aihero.dev/ai-coding-dictionary/stateless)**。它不寫入任何檔案，也不留下任何工作區。它唯一留下的，是你自己腦海中更清晰的想法版本。

## 何時使用它

你可以透過輸入 `/grill-me` 來呼叫它；[Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不會主動使用它。請在**全新對話**中啟動它，而不是在已經讓 Agent 撰寫的計畫之上啟動。

一旦你有一個值得認真對待的想法（一個功能、一個產品方向、一個業務決策、一篇寫作），在深入梳理它涉及的細節之前，就應該使用它。模糊不清並不是等待的理由；它正是工作階段要消除的東西。如果你已經能精確具體地說明它，你就不需要對它進行盤問（grill）。

你需要哪一個盤問技能，取決於你當前面臨的情況：

- **任何事物、任何地方**：`grill-me`。它不需要儲存庫，也不會寫入任何檔案，主題也不必是程式碼。
- **需要對齊的程式碼庫**：[grill-with-docs](https://aihero.dev/skills-grill-with-docs)。相同的訪談，但具備[狀態](https://www.aihero.dev/ai-coding-dictionary/stateful)：它會讀取你的程式碼，並將學到的內容保留在 `GLOSSARY.md` 和 ADR 中。
- **對於單一工作階段而言過於龐大**：[wayfinder](https://aihero.dev/skills-wayfinder)。它將工作規劃成藍圖地圖，並在其中執行盤問工作階段。

保持關閉[計畫模式](https://www.aihero.dev/ai-coding-dictionary/agent-mode)。計畫模式會使 Agent 急於產出計畫，這與保持探詢的狀態正好相反。

## 這是對話，不是面試

此技能負責提問，但**你**才是範圍的掌控者。這是人們容易忽略的部分，它區分了一個將想法轉化為決策的工作階段，與一個產生充滿自信的廢話的工作階段。

失敗模式在於**被動**：對四十個問題都回答「同意、同意、同意」，最後得到一個 Agent 撰寫而你只是點頭認同的計畫。這感覺很有成效，因為過程很長。實際上什麼都沒決定，而且結果帶有其尚未配得的確定性。

保持主動意味著掌握方向。對低於所需精確度的問題進行反駁。當範圍產生偏離時指出。誠實地回答「我不知道」。此技能旨在輔助工程師，而不是取代工程師：產出的成果取決於你回答的品質，而不是提出的問題數量。

相反的錯誤確實存在但較為罕見：在訪談中停留太久，以至於永遠無法進入程式碼階段。

## 可盤問與不可盤問

有些問題可以透過討論來回答。其他問題則不行，再多的盤問也無法讓你得到答案。

「一份長表單還是三個頁面？」以及「這種互動感覺應該如何？」是**不可盤問的**：它們需要實物來感受與反應。當你遇到這類問題時，停止盤問。使用 [prototype](https://aihero.dev/skills-prototype) 建立拋棄式版本，檢視它，然後回來用一句話回答。

試圖透過討論來解決不可盤問的問題，正是工作階段膨脹失控的原因。Agent 不斷重新換句話說，你不斷猜測，而範圍不斷擴大以填補不確定性。

## 運作良好的跡象

- 你對某些內容提出異議。一個你完全沒有提出反駁的工作階段，是你根本不需要的工作階段。
- 問題分幾輪提出，而不是長篇單一連綴，且後面的輪次明顯建立在你之前所說的基礎上。
- 你最終到達了意料之外的方向，因為某個問題揭示了你一直隱含預設的決定。
- 最後你能向未參與這場對話的人為每一個選擇進行辯護。

## 常見問題

**我應該預期會有多少個問題，我又該如何知道它何時結束？**
計算輪次，而不是問題數量。在四輪中回答四十六個問題是很普通的工作階段。當邊界變空時，它就會結束：每個分支都被探訪過，沒有留下任何默默預設的假設。

**它問了我兩百個問題。出了什麼問題？**
通常是因為範圍太大。先要求 Agent 將工作拆解為較小的部分，然後分別對每一個進行盤問。非常長的工作階段也會漂移至**[愚鈍區](https://www.aihero.dev/ai-coding-dictionary/smart-zone)**，在那裡[上下文視窗](https://www.aihero.dev/ai-coding-dictionary/context-window)已經塞得太滿，導致問題品質下降。

**我可以改回一次只問一個問題嗎？**
可以。將此內容新增至你的全域 `CLAUDE.md`：

```
When grilling, ask one question at a time.
```

**如果我真的不知道答案怎麼辦？**
直接說出來。「我不知道」是一個真實的答案，而你無法回答的問題通常表示應該進行原型製作，而不是胡亂猜測。

**在撰寫規格（spec）之前，我需要啟動全新工作階段嗎？**
不需要。工作階段的價值在於你剛剛建立的[上下文](https://www.aihero.dev/ai-coding-dictionary/context)。直接將同一個對話交給 [to-spec](https://aihero.dev/skills-to-spec)。

**模型有差嗎？**
比大多數技能都要重要。盤問依賴於[模型](https://www.aihero.dev/ai-coding-dictionary/model)自身對系統如何崩潰的理解，因此請給它你最好的模型。實作大多遵循上下文，能容忍較便宜的模型。

## 適用定位

`grill-me` 是一個**你可以在任何地方、針對任何事物執行的獨立工具**。無狀態使它具備可攜性：不需要儲存庫、不需要工作區、不需要設定，甚至不假設該想法與軟體有關。人們將它用於業務決策、寫作、下一步該做什麼：任何在腦海中揮之不去的事物。

這種可攜性是它與 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 的全部差別，後者執行相同的訪談，但會讀取程式碼庫進行對齊，並將學到的內容記錄為 `GLOSSARY.md` 與 ADR。兩者都奠基於 [grilling](https://aihero.dev/skills-grilling) 原語上；`grill-me` 是使用者呼叫的入口，不攜帶任何負擔。

如果你盤問的內容確實是軟體，你可以將同一個對話交給 [to-spec](https://aihero.dev/skills-to-spec) 並繼續進入建構流程（這是一個選項，而非此技能的重點）。當你不確定哪種流程合適時，[ask-matt](https://aihero.dev/skills-ask-matt) 會引導你。
