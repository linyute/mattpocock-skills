## 它的功能

`writing-for-agents` 是您撰寫面向 Agent 文件時所參考的規範 — 技能、`AGENTS.md` / `CLAUDE.md`、[spec](https://www.aihero.dev/ai-coding-dictionary/spec)、執行階段提示、README，即任何 [Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 讀取的文件。封裝方式有所不同，但寫作方式並無不同：相同的槓桿使每一個都可預測，因此 Agent 在每次執行中採取相同的**流程**，而不是產出相同的輸出。

它的預設動作是刪除，而不是解釋。要求 Agent 為另一個 Agent 撰寫指令，它會花費大部分字詞解釋 [模型](https://www.aihero.dev/ai-coding-dictionary/model) 已經知道的內容 — 這些行中的每一行都是**無操作 (no-op)**，花費了 [內容](https://www.aihero.dev/ai-coding-dictionary/context) 卻沒有改變任何行為。這份參考規範是發現它們的鏡頭，這就是為什麼它在您已經擁有的文件上與在空白檔案上一樣值得使用的原因。

在 v1.1 之前它被稱為 `writing-great-skills`。改名追蹤了它在底層一直以來的本質：它幾乎沒有任何內容是專門針對 Skill 的。唯 Skill 具備的機制 — Frontmatter、模型呼叫與使用者呼叫的選擇、路由 Skill — 被公開到連結的 `SKILL-MECHANICS.md` 中，僅在您面前的文件是一個 Skill 時您才閱讀它。

## 何時使用它

輸入 `/writing-for-agents`，或者當您建立或編輯 Skill，或是修改 `AGENTS.md` 或 `CLAUDE.md` 時，Agent 會主動使用它。

對於 Agent 讀取的其他所有內容請手動呼叫它：您的文件、規格與 [工單](https://www.aihero.dev/ai-coding-dictionary/ticket)、系統和 [AFK](https://www.aihero.dev/ai-coding-dictionary/afk) 提示。測試為一個問題 — Agent 會讀取這個嗎？— 且文件如何擺在它面前並不重要，無論是指標命名它、人類貼上它，還是它僅僅擺在儲存庫中。要首先查明程式碼庫實際包含的內容，請使用 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) — 此參考規範管理文件如何閱讀，而不是它知道什麼。

## 兩種負載

整個參考規範所圍繞的想法是每個文件和指標所花費的一對預算：

- **內容負載 (Context load)** — 在 Agent 視窗中總是載入材料的成本：`AGENTS.md` 行、Skill 描述、不論是否觸發在每個 [輪次](https://www.aihero.dev/ai-coding-dictionary/turn) 中都擺在內容中的任何內容。
- **認知負載 (Cognitive load)** — 對您的成本：哪些文件存在，以及何時使用每一個文件。您就是索引。這不是要最小化的成本 — 這是人類主導權的代價。

一旦您按這兩種負載進行思考，大多數編撰決策 — 拆分或不拆分、內聯或公開、指向或推動 — 都會變成在不同地方做出的相同權衡。

## 槓桿

- **[內容指標](https://www.aihero.dev/ai-coding-dictionary/context-pointer)** — 保留在內容中命名內容外材料並編碼何時到達它的參考規範。Skill 描述和命名文件的 `AGENTS.md` 行是同一個物件；指標的*字眼*，而不是其目標，決定了 Agent 有多可靠地透過它深入。
- **資訊階層** — 從檔案內步驟、到檔案內參考、再到指標背後公開的參考的階梯。**[漸進式公開](https://www.aihero.dev/ai-coding-dictionary/progressive-disclosure)** 是沿該階梯向下的動作，以便頂部保持清晰易讀。
- **完成條件** — 每個步驟完成條件的清晰度與要求，以及該要求驅動的**腿部功夫 (legwork)**；防範**過早完成 (premature completion)**。
- **引導字詞** — 模型預訓練中已有的緊湊概念 (*tight*、*red*、*tracer bullet*)，Agent 在執行文件時用其進行思考。它錨定兩次：內文中的執行，指標中的呼叫。
- **精簡 (Pruning)** — 逐句針對**重複**、**沉澱 (sediment)** 和**蔓延 (sprawl)** 套用單一真實來源、相關性和無操作測試。

## 常見問題

**`/writing-great-skills` 去哪裡了？**
就是這個 Skill，在 v1.1 中重新命名。在名稱跟上之前，從業者早已將其指向 `AGENTS.md`、文件、規格、工單和執行階段提示；結構、引導字詞和精簡被證明是 Agent 讀取的任何文字的工藝。沒有別名 — 請在新的名稱下重新安裝。

**「為 Agent 寫作」— 所以由 Agent 進行寫作嗎？**
正好相反。您是作者；Agent 是讀者。這正是該文體的全部困難：您正在為已經閱讀過一切的讀者寫作，因此解釋是浪費，精確度是全部的工作。

**難道我不能直接要求 Agent 為我撰寫嗎？**
您可以，且它會產出冗長的東西。單獨放置時，模型會解釋它已經知道的內容，且它不會套用無操作測試，也不會自己尋找引導字詞。在草稿上使用參考規範 — 審查傳遞是其大部分價值的落腳處。

**我要求 Agent 精簡一份文件，它削減了功能。**
被告知要「精簡」的 Agent 會針對長度進行最佳化，因為長度是它們可以看到的東西。無操作測試是行為上的，而不是審美上的：刪除該行並詢問 Agent 的行為是否發生了改變。當句子失敗時，請刪除整句而不是剪裁心中的字詞 — 並透過執行文件而不是爭論來解決關於它的分歧。

**我如何知道何時完成？**
當它可行，且您不再能找到重複、沉澱或無操作時。這裡沒有自動化評估；檢查是手動執行加上失敗模式詞彙表作為診斷。當文件行為不當時，該詞彙表也是修復工具包 — 首先命名失敗模式，然後進行修復。

**這應該存在於 `CLAUDE.md` 還是其他地方？**
詢問您想要支付哪種負載。`CLAUDE.md` 無條件載入到每個 [階段作業](https://www.aihero.dev/ai-coding-dictionary/session) 中；指標背後的材料僅在觸發之前支付指標自己的行成本。十次中有一次適用的任何內容在其他九次中都在支付內容負載。

**我需要為每個新模型重新撰寫我的文件嗎？**
大多數不需要，且過度配對單一模型是其自身的陷阱。針對新模型進行更新通常是另一次無操作傳遞，而不是重新撰寫。

**我的 Skill 僅適用於我建立它的精確任務。**
常見的路徑 — 執行一次工作，然後讓 Agent 將其寫成 Skill — 對單次執行的索引過高，且範例產出過於具體。保留執行作為證據，然後有意識地進行抽象：剝離屬於該儲存庫和那些檔案的內容，並針對該類別的任務進行撰寫。

**英文不是我的第一語言。我會失去引導字詞的優勢嗎？**
不會 — 尋找將最多行為壓縮到最少 [權杖](https://www.aihero.dev/ai-coding-dictionary/token) 中的字詞是參考規範為您做的工作。這是其存在的目的之一。

## 運作良好的指標

- 文件隨著變好而變得更短，您對留下的內容如此之少感到驚訝。
- 您可以指向一個引導字詞，並觀看它在不止一個地方發揮作用。
- 沒有任何內容以任何形式被敘述兩次。重複是文件從未經過測試的最可靠標誌。
- 僅有一個分支需要的參考位於指標背後，而不是主檔案中。

## 適用位置

這是一個隨時可使用的獨立參考規範。它在鏈條中沒有鄰居，因為它部位於整個集合的下方而不是任何一個 Skill 的旁邊：這裡的每個 Skill 都是參照它撰寫的，且其他 Skill 留下的文件（`CONTEXT.md` 及其 ADR、規格、工單）精確地是一旦 Agent 必須讀取它們時它所管理文字。當您不確定哪個 Skill 或流程適合一項任務時，[ask-matt](https://aihero.dev/skills-ask-matt) 會在整個集合中為您引導路線。
