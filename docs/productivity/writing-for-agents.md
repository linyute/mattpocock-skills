## 功能說明

`writing-for-agents` 是你撰寫面向 Agent 之文件時所遵循的參考依據：技能、`AGENTS.md` / `CLAUDE.md`、[規格](https://www.aihero.dev/ai-coding-dictionary/spec)、執行階段提示詞、README，以及任何供 [Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 閱讀的文件。封裝形式各不相同，但寫作法則完全一致：相同的槓桿使每份文件都具備可預測性，讓 Agent 每次執行時都遵循相同的*流程*，而不僅僅是產出相同的輸出。

它的預設做法是刪除，而非解釋。要求 Agent 為另一個 Agent 撰寫指示時，它會花費大部分篇幅去解釋[模型](https://www.aihero.dev/ai-coding-dictionary/model)早已知曉的內容。其中的每一行都是**無效操作（no-op）**，白白消耗[上下文](https://www.aihero.dev/ai-coding-dictionary/context)卻完全沒有改變行為。本參考指引正是用來找出這些多餘內容的透鏡，這也是為什麼它在現有文件上的價值，絲毫不亞於在空白檔案上起步。

在 v1.1 之前它被稱為 `writing-great-skills`。這次更名反映了它底層始終不變的本質：其內容幾乎沒有哪一部分是技能所獨有的。僅限技能的機制（frontmatter、模型呼叫與使用者呼叫的抉擇、路由技能）被移至連結的 `SKILL-MECHANICS.md` 中，只有在你面前的文件本身就是技能時才需要閱讀。

## 何時使用它

輸入 `/writing-for-agents`，或者當你建立或編輯技能、修改 `AGENTS.md` 或 `CLAUDE.md` 時，Agent 會自行使用它。

對於 Agent 閱讀的所有其他內容，請手動使用它：你的文件、規格與[工單](https://www.aihero.dev/ai-coding-dictionary/ticket)、系統提示詞與[離席（AFK）](https://www.aihero.dev/ai-coding-dictionary/afk)提示詞。檢驗標準只有一個問題：Agent 會閱讀這份內容嗎？文件如何出現在它面前並不重要，無論是透過指標提及、人類複製貼上，還是單純存放在儲存庫中。若要從一開始釐清程式碼庫實際包含什麼，請使用 [grill-with-docs](https://aihero.dev/skills-grill-with-docs)；本參考指引規範的是文件的行文閱讀方式，而非它所知曉的內容。

## 兩種負載

整個參考指引所圍繞的核心理念，是每份文件與指標所花費的一對預算：

- **上下文負載**：常態載入材料對 Agent 視窗造成的負擔：`AGENTS.md` 中的一行、技能描述，任何在每[輪](https://www.aihero.dev/ai-coding-dictionary/turn)中無論是否觸發都常駐在上下文中的內容。
- **認知負載**：對你造成的負擔，即哪些文件存在以及何時該使用哪份文件。你就是索引。這不是一種需要最小化的成本：它是人類主導能動性（human agency）的代價。

一旦你從這兩種負載的角度思考，大多數編寫決策（拆分與否、內嵌或揭露、指向或直接置入）都變成了在不同情境下所做的相同權衡。

## 核心槓桿

- **[上下文指標](https://www.aihero.dev/ai-coding-dictionary/context-pointer)**：保留在上下文中、指名上下文之外的材料並規範何時取用它的參考。技能描述與提及文件的 `AGENTS.md` 行是同一種物件；指標的*措辭*（而非其指向的目標）決定了 Agent 透過它取用內容的可靠程度。
- **資訊階層**：從檔內步驟、檔內參考資料，到指標後揭露的參考資料的階梯階層。**[漸進式揭露](https://www.aihero.dev/ai-coding-dictionary/progressive-disclosure)** 是沿著階梯往下移動的機制，以便頂層保持清晰易讀。
- **完成條件**：每個步驟完成狀態的明確性與嚴謹度，以及該要求所驅動的**繁複查證工作**；這是防止**過早宣告完成**的防線。
- **前導關鍵字（Leading words）**：模型預先訓練中已具備的精煉概念（例如 *tight*、*red*、*tracer bullet*），Agent 在執行文件時會以此作為思考錨點。它發揮雙重錨定作用：內文中的執行與指標中的呼叫。
- **精簡修剪**：單一事實來源、相關性，以及逐句套用的 no-op 檢驗，以對抗**重複內容**、**歷史沉積物**與**內容蔓延**。

## 常見問題

**`/writing-great-skills` 去哪裡了？**
它就是這個技能，在 v1.1 中重新命名。早在名稱更新之前，實踐者就已經將它應用於 `AGENTS.md`、文件、規格、工單以及執行階段提示詞；架構、前導關鍵字與精簡修剪事實上適用於 Agent 閱讀的任何文字。沒有別名。請以新名稱重新安裝。

**「為 Agent 寫作」：意思是 Agent 負責寫作嗎？**
恰好相反。你是作者，Agent 是讀者。這正是此類文體的全部難題所在：你是在為一個早已博覽群書的讀者寫作，因此解釋是浪費，精確才是全部職責所在。

**難道我不能直接要求 Agent 幫我寫嗎？**
你可以，但它會產出冗長繁複的內容。若任由模型自行發揮，它會解釋它早已知曉的事情，而且不會主動套用 no-op 檢驗或使用前導關鍵字。請將本參考指引運用於草稿上：審查審閱階段正是其發揮絕大部分價值的地方。

**我要求 Agent 精簡文件，結果它刪除了功能性內容。**
被要求「精簡」的 Agent 會以長度為最佳化目標，因為長度是它們看得見的東西。no-op 檢驗著重於行為層面而非美學層面：刪除該行並詢問 Agent 的行為是否發生改變。當一個句子未能通過檢驗時，直接刪除整句話，而不是從中修剪單字，並透過實際執行文件來化解對此的分歧，而不是徒費唇舌爭論。

**我如何知道何時算完成？**
當它能正常運作，且你再也找不到重複內容、沉積物或無效操作時。這裡沒有自動化評估；檢驗方式是手動執行加上以失敗模式詞彙進行診斷。當文件表現異常時，該詞彙同時也是修復工具箱：先指出具體的失敗模式，然後針對其進行修復。

**這應該放在 `CLAUDE.md` 還是其他地方？**
問問自己你想支付哪種負載。`CLAUDE.md` 會無條件載入到每個[工作階段](https://www.aihero.dev/ai-coding-dictionary/session)中；指標後方的材料在觸發前只消耗指標本身的單行成本。任何在十次情境中僅適用一次的內容，其餘九次都在白白支付上下文負載。

**我需要為每個新模型重寫文件嗎？**
大致上不需要，而且過度配適單一模型本身就是個陷阱。針對新模型的更新通常只是另一輪 no-op 檢驗過濾，而非重新撰寫。

**我的技能只能用於建立它時所針對的精確任務。**
常見的途徑（先做一次工作，然後讓 Agent 將其編寫為技能）會對該單次執行過度著墨，導致範例過於具體。保留該次執行作為佐證，然後刻意進行抽象化：剝離屬於該儲存庫和那些檔案的特定內容，為該類任務撰寫通用指引。

**英文不是我的母語。我會失去前導關鍵字的優勢嗎？**
不會。找出能以最少 [Token](https://www.aihero.dev/ai-coding-dictionary/token) 蘊含最多行為的詞彙，是本參考指引為你分擔的工作。這正是它的用途之一。

## 運作良好的跡象

- 文件越改進越精簡，而且你對最後剩下的精簡程度感到驚訝。
- 你可以指著一個前導關鍵字，並看到它在不止一處發揮作用。
- 沒有任何內容以任何形式被重複敘述兩次。重複是證明文件從未經過測試的最可靠跡象。
- 僅有單一分支需要的參考資料位於指標後方，而不是放在主檔案中。

## 適用定位

這是一份隨時可用的獨立參考指引。它位於整套體系底層，而不是附屬於任何單一技能：這裡的每個技能都是依照它撰寫的，而其他技能所留下的文件（`GLOSSARY.md` 及其 ADR、規格、工單）一旦需要由 Agent 閱讀，就完全受到它的規範。它的唯一直接呼叫者是 [retro](https://aihero.dev/skills-retro)，後者在提出任何引導檔案或技能之前都會載入它。當你不確定哪種技能或流程適合某項任務時，[ask-matt](https://aihero.dev/skills-ask-matt) 會為你引導整套體系。
