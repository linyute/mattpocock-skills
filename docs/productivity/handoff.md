## 功能說明

`handoff` 會將你目前的對話壓縮成一份**交接文件**：一個 Markdown 檔案，寫入你作業系統的暫存目錄而不是工作區中，讓全新 [Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 可以讀取以接續工作。

它換取的是**可攜性**，而非壓縮率。這使得該技能的適用情境比聽起來更為狹窄。只有在工作必須*轉移*時你才需要檔案：轉移到新的[測試載具](https://www.aihero.dev/ai-coding-dictionary/harness)、新的目錄、同事，或是你想分支出去的附屬任務。如果沒有任何東西需要轉移，你就不需要交接：保留在[工作階段](https://www.aihero.dev/ai-coding-dictionary/session)中、`/clear`、[Subagent](https://www.aihero.dev/ai-coding-dictionary/subagent) 以及 `/compact` 涵蓋了普通的階段結束情境，而且 `/compact` 比此技能更常用於處理該情境。

## 何時使用它

你可以透過輸入 `/handoff` 來呼叫它；Agent 不會自行呼叫它。傳入一段關於下一個工作階段目的之備註，文件就會針對該目的進行撰寫。

四種情境構成了全部的觸發條件：

| 情境 | 為何需要檔案 |
| --- | --- |
| 更換測試載具（Claude → Codex） | 新的測試載具無法檢視舊有的[上下文](https://www.aihero.dev/ai-coding-dictionary/context) |
| 移動至不同的目錄或儲存庫 | 原型目錄是常見的情境 |
| 將工作傳送給同事 | 他們需要可供閱讀的文件 |
| 分支階段中途發現的附屬任務 | 你繼續工作；由第二個 Agent 接手分支任務 |

至於其他任何情況（相同的測試載具、相同的目錄、你已完成[盤問](https://www.aihero.dev/ai-coding-dictionary/grilling)並準備進入實作），使用 `/compact` 才是正解。[ask-matt](https://aihero.dev/skills-ask-matt) 提供了在階段邊界時這全部五個選項的有序決策樹。

## 分支是人們容易忽略的用法

此技能的描述讀起來像是工作階段恢復：撰寫摘要、在此結束、在彼處恢復。這樣理解會讓它看起來像是比較差的 `/compact`，因而被草草略過。分支情境才是值得了解的重點。你**保留在你的工作階段中**，並將累積的上下文複本交給平行工作的第二個 Agent。

這就是繞道使用 [prototype](https://aihero.dev/skills-prototype) 的做法。你正深入進行設計對話，遇到只有執行程式碼才能解決的問題，且你不想耗損辛苦建立的討論對話串去找出答案。交接給原型工作階段、取得答案、交回答案，並在原始對話串中引用它。兩次跨越、一個活躍對話，無需重新解釋。

在階段邊界時，五個選項中的三個保留了不同的東西：`/compact` 保留你的意圖，`/clear` 什麼都不保留，`/handoff` 則保留工作轉移的能力。

## 哪些內容會轉移，哪些不會

該文件承載了即時的對話脈絡（正在進行的項目、原因以及下一步），加上一個列出下一個 Agent 應該使用的**建議技能**章節。敏感資訊在寫入前會被隱藏移除。

它刻意不承載任何已經記錄下來的內容。規格、計畫、ADR、issue、commit 和 diff 都是透過路徑或 URL 來引用，絕不複製。這使檔案保持精簡，並將已定案的細節保留在單一位置，避免兩處產生分歧。

## 常見問題

**交接（handoff）還是壓縮（compact）？**
除非有東西需要轉移，否則使用 `/compact`。留在同一個任務上是 compact，而不是 handoff：相同的測試載具、相同的目錄，且你需要留在迴圈中，這正是多數日子裡階段邊界決策樹的落點。`/handoff` 的優勢並非摘要寫得更好，而是在於產出的結果是一個檔案，能讓你帶到 `/compact` 無法觸及的地方。

**那麼 compact、clear 和 handoff 之間的實際區別是什麼？**
三者保留的東西截然不同。`/compact` 壓縮此上下文，讓你在全新視窗中繼續前進：保留意圖。`/clear` 清空視窗並從零開始：當先前所有內容皆可拋棄時是正確的，若非如此則是一去不復返。`/handoff` 寫出一個可攜式檔案：使工作得以在轉移到其他地方後延續。請注意，這三者都將**[第一手來源](https://www.aihero.dev/ai-coding-dictionary/primary-source)**（對話發生的原貌）轉變為**[第二手來源](https://www.aihero.dev/ai-coding-dictionary/secondary-source)**（對話的摘要）。繼續下去是唯一不改變來源性質的舉動，這就是為什麼它是第一個應該優先考慮或排除的選項。

**我的交接檔案去哪裡了？**
暫存目錄，這是該技能最常被回報的摩擦點：路徑很長、因作業系統而異，且在 Windows 上 Agent 有時需要嘗試數次才能找到正確路徑。在繼續進行之前，要求取回路徑並將其保留。使用暫存目錄是刻意為之：交接是一份過渡文件，而非你需要維護的成品（artifact）。它也不是持久的檔案；請參閱下一個問題。

**我的交接檔案在工作階段之間消失了。**
某些環境會在工作階段之間清理暫存目錄（Codex 是回報的案例），且重新開機後 `/private/tmp` 就會被清除。如果下一個工作階段不會在一小時內啟動，或是在不同的測試載具下啟動，請在檔案寫入後立即自行將其複製到持久的地方。這同樣適用於該文件所*指向*的任何內容：引用了暫存目錄中其他檔案的分派，是下一個 Agent 無法追蹤的分派。

**我實際上該如何將它交給下一個 Agent？**
開啟全新工作階段並將其指向該路徑：讀取此檔案，然後繼續。請指向該檔案，而不是將摘要貼入 shell 指令中：包含反引號或 `$(...)` 的摘要在插入到 `claude "<summary>"` 時會被破壞，而常見的失敗情況是默默被截斷而非報錯，導致新 Agent 在毫無察覺的不完整指示下開始。

**這與 `/branch`、`--fork-session` 或內建的 `/handoff` 相同嗎？**
類似，但不相同，且 `/branch` 在這裡不是已發布的技能；`/handoff` 是正式名稱。分支會繼承上下文的精確複本；此技能則在檔案中針對宣告的下一個任務產生*目標導向*的壓縮。在分支即可滿足的情況下（相同機器、相同測試載具、相同目錄），分支的工作量較少。一旦目的地是分支無法觸及的地方，檔案就勝出了。

**何時內容應該改放進 `CLAUDE.md`？**
問問自己下個月它是否依然成立。`CLAUDE.md` 是關於專案的常態上下文，無論是否相關都會載入到每個工作階段中。交接是針對進行中的單項工作，一旦該工作著陸即宣告作廢。需要不斷重複解釋的事實屬於 `CLAUDE.md` 的範疇；半完成的任務則是交接的範疇。

**它記錄了「做了什麼」，而不是「為什麼這樣做」。**
這是合理且經常出現的批評。兩件事會有所幫助：傳入引數（告訴它下一個工作階段的目的），讓與*該目的*相關的推理得以保留而非被抹平。並且注意工作階段從未實際驗證的自信宣告：「X 尚未建構」、「Y 已完成」。下一個 Agent 會將該文件視為合約且不會重新查證，因此被寫作事實的信念會成為後續所有工作的錯誤前提。在交接之前務必先閱讀該文件，並將你僅是假設的任何內容降級標註。

**為什麼它是技能而不是斜線指令？**
兩種皆可行；它們適合不同的情境。作為技能，它透過與此處所有其他內容相同的安裝路徑進行發布與更新，這使得它具備可共享性；Agent 不會自行觸發它的限制是由其 frontmatter 所設定，而非由底層機制所致。

## 運作良好的跡象

- 該文件僅佔對話的一小部分，且規格、issue 與 diff 是以路徑和 URL 的形式出現在其中，而非複製的文字。
- 你可以在未開啟原始工作階段的情況下直接閱讀它，並清楚知道下一步要做什麼。
- 全新的 Agent 直接開始工作，而不是要求你重新解釋設定。
- 在分支情境中，當你返回原始工作階段時，它仍然完好無損地保留在那裡。
- 建議技能章節指出了你自己也會選擇使用的技能。
- 其中沒有任何金鑰、權杖或密碼。

## 適用定位

`handoff` 是一個**隨時可用的獨立工具**，它存在於工作階段之間的縫隙中，而不是建構鏈內部，但其用途較為專一，老實說你在階段邊界時使用它的頻率會低於其他四個選項。它最親近的夥伴是 [prototype](https://aihero.dev/skills-prototype)，因為原型存在於其自身的目錄中，而往返的跨越正是此技能的用武之地。當你處於邊界且不確定要繼續、清除、交接、委派還是壓縮時，[ask-matt](https://aihero.dev/skills-ask-matt) 提供了排序這五個選項的決策樹，並為你引導其他工具。
