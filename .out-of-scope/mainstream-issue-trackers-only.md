# 問題追蹤器整合僅限於主流工具

`setup-matt-pocock-skills` 僅針對**主流**問題追蹤器提供第一類支援。要求新增對小眾、新興或單一廠商實驗性追蹤器的支援均屬於超出範疇。

## 為何這屬於超出範疇

每個問題追蹤器後端都在技能中硬式編碼了 CLI 形式（指令、旗標、輸出解析）。每個新的後端都是永久的維護層面，因為隨著工具 CLI 的演進它必須持續運作，且必須持續針對 `/to-spec`、`/to-tickets`、`/triage` 及相關技能進行測試。這種成本僅值得為有相當比例的使用者實際擁有的追蹤器付出。

「主流」是一種判斷考量，而非數字門檻：

- GitHub、GitLab 與 Backlog.md 是我們認為屬於主流的工具：廣為人知、廣泛使用，且早已脫離實驗階段。
- 一個擁有幾百顆 GitHub 星星的全新面向代理工具則不是，無論其設計多麼有趣。

星星數、年份與下載次數在做出決定時是有用的訊號，但都不是絕對規則。規則是：一般的工程師能否認出這個工具，並有可能為其團隊選擇它？

針對非主流追蹤器的權宜方案已經存在：

- 用於輕量化儲存庫內追蹤的 `local markdown`。
- 用於想要自行串接的使用者的 `other/custom`。

兩者皆不需要核心技能知曉特定工具。
